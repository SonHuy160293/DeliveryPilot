## Module-wide data conventions

These apply to every table in the module unless an entity says otherwise.

1. **Keys.** Primary key `Id`, UUID version 7, generated by the application. Child tables also expose an alternate key that includes their tenant and parent (see 2).
2. **Tenant on every row.** Every table carries `OrganizationId` (owning vendor workspace, scalar Identity ID). Parents expose the alternate key `(OrganizationId, Id)`; children reference parents with **composite** foreign keys `(OrganizationId, ParentId)`, so the database rejects a child that points at another tenant's parent ([PRJ-05](design-decisions.md#prj-05)). Project-scoped rows also carry `ProjectId` (ADR-001 D-07).
3. **Cross-module references are scalar IDs** with no foreign key: `OrganizationId`, `UserId`, `ClientOrganizationId` (Identity). Local foreign keys are allowed across the module's schemas, e.g. Project → Engagement (D-08).
4. **No copies of Identity data.** Names and emails of users are read from Identity when needed, never stored ([PRJ-12](design-decisions.md#prj-12)). Contact and stakeholder emails entered by vendor users are business data and are stored.
5. **Time.** Instants are UTC `DateTimeOffset` (`…At`). Calendar dates are `date` (`…On` / `…Date`).
6. **Concurrency.** Aggregate roots and independently edited children carry `Version` (bigint, optimistic concurrency token, starts at 1). Rules that span several rows use a row lock on the aggregate root inside the command transaction ([erd.md, invariants](erd.md#invariants-and-how-they-are-enforced)).
7. **Statuses** are text codes with check constraints. Rows are never physically deleted by product behavior; they end through a status or `…At`/`…ByUserId` pair.
8. **History.** Every attributable change appends one row to the context's event table (`engagement.EngagementEvents`, `project.ProjectEvents`) in the same transaction ([PRJ-03](design-decisions.md#prj-03)). Secrets, proofs and link codes never appear in events.
9. **Secrets** (guest-invitation proofs, link codes) are stored only as a 32-byte SHA-256 verifier.
10. **Naming.** Plural PascalCase tables, PascalCase columns, quoted identifiers, schema per context (D-08).
11. **Idempotent creation.** Create-engagement and create-project retries use the existing `reliability.IdempotencyRecords` ([PRJ-13](design-decisions.md#prj-13)); no per-feature attempt table.
