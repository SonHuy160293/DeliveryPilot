# FR-DP-015-007 — Enforce guest visibility on every read path

**Provenance:** Drafted 2026-11-10 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user on 2026-11-10 (decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall deny a guest any information about a project that is not part of the default view, granted by the guest's role, or currently shared, regardless of the route used to request it.

## Preconditions and trigger
Any read made by a user acting through a guest participation.

## Main behavior
The same rule applies to direct access by identifier, lists, counts and totals, search, navigation through relationships, derived summaries and indicators, exports, AI retrieval and explanations, and notification content. An item that is not visible is not found; its existence, count, title and identifier are not revealed. Being mentioned in a comment or named as a stakeholder or engagement contact grants nothing.

## Validation, business rules and authorization
- BR-003, BR-004, BR-055; workflow §4.3 ("a derived summary must not reveal information that the recipient is not authorized to see").
- Tenant and project filters are applied before the sharing check (ADR-001 D-07).
- A guest of project P has no access to project Q of the same workspace.
- This requirement is justified directly by BR-004 and NFR-001/002 as well as by its user requirement.

## Failure and edge cases
- Revoked or left guest: every read is denied from the next request, including previously shared items.
- Identifier of an unshared item of the guest's own project: not found, identical to an unknown identifier.
- Workspace Owner or member without project participation gains nothing from shares; shares address guests only.

## Verification criteria
- Guessing identifiers of unshared brief items, stakeholder entries, the engagement, other projects and other workspaces always yields not found.
- No guest response contains a count that includes unshared items.
- A revoked guest cannot read an item that is still shared.
