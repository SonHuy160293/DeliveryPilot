# FR-DP-015-009 — Keep item types of later features internal until they join the sharing rules

**Provenance:** Drafted 2026-11-10 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user on 2026-11-10 (decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall treat every project item type introduced by another feature as invisible to guests until that feature defines, under these sharing rules, whether and how the type is shared or published.

## Preconditions and trigger
A feature adds an item type to a project (for example backlog items, requirement revisions, discussions, Sprint Review records, risks, health indicators).

## Main behavior
A new type is internal by default. Its owning feature states: whether it is shareable; who may share it; whether guests see live content or a published revision; which fields are never client-visible; and how FR-DP-015-004, 005, 007 and 008 apply. Guest-facing behavior beyond reading (commenting, reviewing, deciding) is defined by that feature and never follows from visibility alone.

## Validation, business rules and authorization
- **User-selected (OQ-015-01):** one common rule set.
- BR-004, BR-055; workflow §4.3; visibility, review assignment and decision authority stay separate (BR-019).
- This is a cross-feature constraint derived from BR-004 and UR-DP-015-003, verified in each later feature's contract and tests, not by a behavior of its own.

## Failure and edge cases
- A feature that ships a new type without a sharing definition: guests see nothing of it.

## Verification criteria
- For each later feature contract, a review confirms a stated sharing definition or an explicit "never shared".
- A guest test for each new type proves default invisibility.

## Open questions
- Requirements open questions 3 and 12 (which further resources, and which risk and health information, are shared) belong to the owning features.
