# FR-DP-015-004 — Withdraw a shared item

**Provenance:** Drafted 2026-11-10 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user on 2026-11-10 (decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let an authorized vendor participant withdraw a shared item so that guests can no longer read it, keeping the record of when it was shared and withdrawn.

## Preconditions and trigger
The caller has share authority on the project; the item is currently shared.

## Main behavior
Withdrawing takes effect on each guest's next request. The item itself is unchanged. The withdrawal records actor, UTC time and an optional reason. The item can be shared again later; each period is kept in history.

## Validation, business rules and authorization
- Same authority as FR-DP-015-003.
- Withdrawing cannot undo what a guest already read or copied; the product states only that access ended.

## Failure and edge cases
- Item not shared: no change.
- Engagement summary: also withdrawn automatically when the project's engagement changes or is removed while Draft (FEAT-DP-004), because the share named the previous engagement.

## Verification criteria
- After withdrawal a guest's request for the item behaves as if it never existed for them.
- History shows both the share and the withdrawal.
