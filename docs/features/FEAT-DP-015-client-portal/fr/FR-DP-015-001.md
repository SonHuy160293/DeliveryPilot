# FR-DP-015-001 — Show a guest the projects they are admitted to

**Provenance:** Drafted 2026-11-10 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user on 2026-11-10 (decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall show a signed-in user, in one portal view, every project where they hold an active guest participation, across vendor workspaces, with enough information to choose one.

## Preconditions and trigger
An authenticated user with a current session opens the portal. No workspace membership is needed.

## Main behavior
List each project with its name, status, the user's project roles, whether the user is its client Product Owner, and when they were admitted. Projects where the participation ended (revoked or left) are not listed. A user with no guest participation sees an empty portal, not an error.

## Validation, business rules and authorization
- BR-003: no workspace membership is created or required. ADR-001 D-07.
- The list is built only from the user's own active guest participations (FEAT-DP-004).
- The vendor workspace's name is not shown unless a later decision adds it; Projects holds no copy of it.

## Failure and edge cases
- Revoked guest: the project is gone on the next request.
- A user who is a vendor member of one workspace and a guest in another sees only the guest projects here.

## Verification criteria
- A guest of projects P and R (different vendors) sees both and nothing else.
- After revocation from P, only R is listed.
- A user with no guest participation sees an empty list.

## Open questions
- None blocking. The vendor workspace name is not shown; adding it later would need an Identity organization lookup.
