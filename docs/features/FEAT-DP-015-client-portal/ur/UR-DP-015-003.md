# UR-DP-015-003 — Be certain that unshared information cannot reach a client

**Provenance:** Drafted 2026-11-10 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user on 2026-11-10 (decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
One leaked internal note, estimate or another client's data would end a vendor's trust in the product. Leaks rarely come from the main screen; they come from lists, counts, links, search results, summaries and notifications (workflow §4.3; requirements validation use case).

## User need
As a vendor workspace Owner, I need a guarantee that a guest can obtain only the default view and explicitly shared items of their own project by any route, so that I can admit client people without reviewing every screen.

## Business value and observable outcome
Every guest read is denied unless covered by the default view, the guest's role or a current share. Validation: the security scenarios of requirements §10 (journeys 2 and 9) pass, including ID guessing and revoked guests.

## Scope, constraints and exceptions
- Applies to direct access, lists, counts, search, relationship navigation, derived summaries, exports, AI retrieval and notifications (workflow §4.3).
- Item types added by later features are internal until that feature defines how they are shared under these rules.
- NFR-001, NFR-002; ADR-001 D-07.

## Evidence and validation
**Agreed direction:** BR-003, BR-004, workflow §4.3. **Proposed rule:** BR-055.
