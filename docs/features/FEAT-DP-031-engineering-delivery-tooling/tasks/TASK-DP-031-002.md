# TASK-DP-031-002 — Module verification script with database-skip gate

## Objective and source contract
Add `scripts/Verify-Module.ps1`, one command that verifies a module for a task:
- builds its test project and runs its tests, with counts read from TRX;
- runs the architecture check in the same process;
- runs docs validation;
- prints one JSON summary.

With `-RequireDb`, the run **fails** when the module's PostgreSQL variable is unset or any test was skipped because of it. A false green from skipped database tests becomes a visible failure.

Sources: NFR-004 (integrity checks must be testable, which needs the PostgreSQL-backed tests to really run), NFR-011, and [FEAT-DP-031](../feature.md). This is a technical enabler with no user story. G1–G3 are skipped.

## Behavior and invariants
Parameters:
- `-Module` (required; `Identity|Notification|Projects|Gateway|HttpClient`).
- `-RequireDb` (switch).
- `-NoBuild` (switch; passed through to `dotnet test`).
- `-Filter` (string; passed to `dotnet test --filter` for focused runs).
- `-SkipArchitecture`, `-SkipDocs` (switches; the summary records them as `skipped`).
- `-OutFile` (path; also writes the JSON summary there).

Steps, in order. Every step always runs and is recorded, even after an earlier failure, so the summary is complete.
1. **db-precheck.** When `-RequireDb` is set and the module has a database variable that is unset or blank, the step fails with the message "Set {VARIABLE} to an isolated PostgreSQL 18 database". When the module has no database variable, `-RequireDb` is recorded as `not-applicable`. **Never print or record the variable's value.** Record only `dbConfigured: true|false`.
2. **build** (unless `-NoBuild`): `dotnet build {testproject} --nologo --verbosity quiet`.
3. **test**: `dotnet test {testproject} --no-build --nologo --verbosity quiet --logger "trx;LogFileName=verify.trx" --results-directory artifacts/verify/{module}/{yyyyMMdd-HHmmss}`. Use `--no-build` only when the build step ran or `-NoBuild` was given. Parse the TRX:
   - `ResultSummary/Counters` gives `total`, `passed`, `failed` and `notExecuted` (reported as `skipped`).
   - Each `UnitTestResult[@outcome='NotExecuted']` skip message from `Output/StdOut` or `Output/ErrorInfo/Message`: check the TRX that xUnit actually produces. Group them into `skipReasons` (message → count).
   - A skip is a **database skip** when its message contains the module's database variable name.
4. **architecture** (unless `-SkipArchitecture`): call `& "$PSScriptRoot/Test-Architecture.ps1"` in the same process inside `try/catch`. Never start a nested `powershell`/`pwsh`.
5. **docs** (unless `-SkipDocs`): `python tools/docs.py validate` from the repository root. If no `python` is on PATH, record `not-run` with a reason. This is not a failure.

Result:
- `failed` when any step failed, `tests.failed > 0`, or (`-RequireDb` and `dbSkipped > 0`).
- Otherwise `passed-with-skips` when `skipped > 0`, else `passed`.

Exit code: 0 for `passed`/`passed-with-skips`, 1 for `failed`, 2 for invalid usage.

Output:
- Human-readable step lines, then a final line `VERIFY-SUMMARY {compact JSON}`.
- JSON fields: `module`, `commit` (`git rev-parse HEAD`, or null), `startedAt`/`finishedAt` (UTC ISO-8601 `Z`), `requireDb`, `dbVariable`, `dbConfigured`, `steps[{name, command, status (passed|failed|skipped|not-run|not-applicable), exitCode, durationSeconds}]`, `tests{total, passed, failed, skipped, dbSkipped, skipReasons}`, `trxPath` (repository-relative), `result`.
- `command` strings must never contain connection strings or secrets.

Compatibility:
- Runs under Windows PowerShell 5.1 and PowerShell 7 on Windows and Linux. Don't use `??`, the ternary operator or `-Parallel`.
- Use `Join-Path` for paths.
- `$ErrorActionPreference = 'Stop'`, but each step's failure is caught and recorded instead of stopping the script.

## Persistence, events and integrations
Only TRX files under the git-ignored `artifacts/verify/` and the optional `-OutFile`. Nothing is written to the database apart from what the existing tests do. No network access other than what the tests already use.
