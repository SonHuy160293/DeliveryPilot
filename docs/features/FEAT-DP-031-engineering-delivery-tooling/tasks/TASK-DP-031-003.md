# TASK-DP-031-003 — Record verification evidence through the task lifecycle

## Objective and source contract
Add `verify-task` to `tools/docs.py`. It runs (or ingests the result of) `scripts/Verify-Module.ps1` for an `in_progress` task and writes a generated, standard subsection into the task's `## Execution evidence`. `submit-task` and `complete-task` then accept a task only with fresh, non-failing evidence. Skipped database tests need an explicit, recorded acceptance. Sources: NFR-004, NFR-011, [FEAT-DP-031](../feature.md). This is a technical enabler with no user story.

## Behavior and invariants
**`verify-task --id X --module M [--require-db] [--filter F] [--from-summary path]`**
- Refused unless the task is `in_progress`.
- Without `--from-summary`:
  - Run the script. Use `pwsh -NoProfile -File scripts/Verify-Module.ps1 …` when `pwsh` is on PATH. Otherwise use `powershell -NoProfile -ExecutionPolicy Bypass -File …`. The policy argument applies to that child process only; never change machine or user policy.
  - Always pass `-OutFile` to a temp file, then parse it.
- With `--from-summary`: read a JSON summary saved from an earlier manual run. This supports environments where Python can't start PowerShell.
- Writes or replaces the subsection `### Verify-Module: {Module}` inside `## Execution evidence`. It creates the section before `## Unresolved decisions` if missing. Re-running for the same module replaces only that subsection. Other modules' subsections and hand-written notes stay byte-for-byte unchanged.
- Subsection content, plain Markdown with no angle brackets:
  - `- Run: {finishedAt} at commit {commit-short}; result **{result}**`
  - `- Command: {script command line}`. Reuse the summary's `command` strings. They never contain secrets.
  - A table of steps with status and duration.
  - `- Tests: {passed} passed, {failed} failed, {skipped} skipped ({dbSkipped} database)`
  - `- Skip reasons:` one bullet per reason, with its count, at most 10.
  - `- TRX: {trxPath}`
- Exit code: 0 when the run result is `passed`/`passed-with-skips`, 1 when `failed`. The evidence is written either way, so a failure is recorded too.

**Freshness rule** (`evidence_ok(task)`), shared by `submit-task` and `complete-task`, in place of TASK-DP-031-001's "an evidence section exists" check:
- At least one `### Verify-Module:` subsection exists.
- Every such subsection's run time is at or after `started_at`.
- None has result `failed`.
- Where a subsection shows `database > 0` skipped, the task must carry a line `- Accepted skips: {reason}` in that subsection.
- Exception: a `- No verification: {reason}` line in `## Execution evidence` replaces the whole rule. Use it for documentation-only tasks.

**Escape hatches:**
- `submit-task --accept-skips "reason"` writes the `Accepted skips` line into each subsection that has database skips.
- `submit-task --no-verify "reason"` writes the `No verification` line.
- Both require a non-empty reason, and both are visible in review.
- `complete-task` re-runs the freshness rule; it takes no flags.

**Invariants:**
- No status other than the task's own changes.
- Connection strings are never written: only the summary's sanitized fields are copied.
- Existing free-form evidence headings (for example `## Execution evidence — 2026-11-10`) still count as the section for `section_text` (prefix match).

## Persistence, events and integrations
Writes only the target task file, atomically (same helper as TASK-DP-031-001). It starts one child process (the verification script) and reads the JSON file that process wrote.

## Test matrix
Add the tests to `tools/docs_validation/test_docs.py`, using `--from-summary` with fixture JSON. Tests must not need PowerShell or .NET.
- **Positive:**
  - A `passed` summary writes the subsection. `submit-task` and `complete-task` then succeed, and `validate` passes (no placeholder false positive).
  - Two modules give two subsections. Re-running one replaces only that one, and a hand-written paragraph stays unchanged.
- **Freshness:** a summary whose `finishedAt` is before `started_at` makes `submit-task` refuse.
- **Failure:**
  - A `failed` summary writes evidence, exits 1, and `submit-task` refuses.
  - Fixing the problem and re-running with `passed` unblocks it.
- **Database skips:**
  - A `passed-with-skips` summary with `dbSkipped: 3` makes `submit-task` refuse.
  - `submit-task --accept-skips "no PG in this env"` succeeds and writes the line.
  - An empty reason is refused.
- **No verification:** `submit-task --no-verify "docs-only task"` succeeds without any subsection.
- **Status gate:** `verify-task` on a `pending` or `done` task is refused, and the file is unchanged.
- **Secrets:** a summary fixture with an extra unexpected field holding a fake connection string; the field is not copied into the task.
- **Legacy:** TASK-DP-025-001's `## Execution evidence — 2026-11-10` heading is found by `section_text`. Repository `validate` still reports 0 errors.
- **Manual end-to-end (record in evidence):** on a scratch copy of a real `pending` task, run `start-task` → `verify-task --module Projects` (real script, with and without `--require-db`) → `submit-task` → `complete-task`. Then discard the scratch copy.
