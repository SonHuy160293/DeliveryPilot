# UR-DP-004-002 — Capture the project brief, Product Goal and cadence progressively

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
LC01 needs a charter and Product Goal, but teams rarely have every detail on day one. The workflow allows a Draft project with only a name and purpose, with missing information kept visible (workflow §5.1).

## User need
As a vendor PM, I need to start a project with just a name and purpose and progressively capture the problem, objectives, scope and exclusions, assumptions, constraints, Product Goal and Sprint length, so that gaps stay visible until the project is ready.

## Business value and observable outcome
Missing brief items are visible; the Product Goal and Sprint length exist before the project becomes Active (FR-DP-004-012).

## Scope, constraints and exceptions
- Readiness policy, not a mandatory waterfall phase (workflow §5.1).
- **User-selected (OQ-004-12):** Sprint length in whole weeks 1–4, default 2 (BR-028 maximum one month).
- Structured discovery is FEAT-DP-005 (V1).

**User-confirmed:** Q7/Q24, workflow §5.1. **User-selected:** cadence defaults (2026-11-09).
