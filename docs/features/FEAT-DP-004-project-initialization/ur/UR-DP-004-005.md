# UR-DP-004-005 — Record project stakeholders and their responsibilities

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
LC01 asks for a stakeholder map and responsibility/decision matrix. Many stakeholders (client sponsor, dependency owners) never sign in, so the map cannot rely on user accounts.

## User need
As a vendor PM, I need to record project stakeholders with their side, organization, responsibilities and decision areas, whether or not they have accounts, so that everyone knows who decides and who must provide inputs.

## Business value and observable outcome
The stakeholder list shows each stakeholder's responsibilities; recording a stakeholder grants no access.

## Scope, constraints and exceptions
- **User-selected (OQ-004-11):** basic register; no RACI, communication calendar or kickoff record in MVP.
- A stakeholder entry is information, not a grant (BR-004); personal data minimization (NFR-008).
