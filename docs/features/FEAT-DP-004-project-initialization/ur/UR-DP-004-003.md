# UR-DP-004-003 — Assign the delivery team and project roles

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
Workspace membership must not reveal every project (BR-003), and a PM of project X must not administer project Y (workflow §4.1). Teams need explicit project participation with project roles separate from job titles (BR-005).

## User need
As a project administrator, I need to add workspace members to my project with project roles, change their roles and remove them, so that only the delivery team sees and changes project work.

## Business value and observable outcome
Only participants see the project; removing a participant stops future access while keeping their history (BR-007); a project never loses all administrators silently.

## Scope, constraints and exceptions
- **User-selected (OQ-004-04):** fixed template roles (Project Administrator, PM, BA, Developer, QA, DevOps, Viewer), additive, no custom project roles in MVP.
- **User-selected (OQ-004-09/14):** workspace removal denies access immediately; the last administrator cannot be removed; an audited workspace-Owner recovery appoints a new administrator from participants.
- Project roles are Projects-owned; Identity knows nothing about projects (SCOPE-04, ADR-001 D-03).

## Evidence and validation
**User-confirmed:** Q2/Q3/Q5/Q6 and workflow §4.1–§4.2. **User-selected:** role model and continuity (2026-11-09).
