# UR-DP-004-001 — Create a Scrum project under a client engagement or as internal work

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
Vendors start delivery for a signed agreement but currently set up projects in tools that know nothing about the engagement, the owning workspace boundary or who may see them. **User-confirmed:** Owner/Admin or a delegated Create Project permission creates projects and the creator initially administers them (Q2/Q3/Q5/Q6); Scrum is the only framework (D7); a client project belongs to at most one engagement and internal projects need none (BR-046).

## User need
As an authorized vendor workspace member, I need to create a Scrum project either under one client engagement or as an internal project, so that delivery work starts inside the right tenant and commercial context with a known administrator.

## Business value and observable outcome
Every client project is traceable to its engagement, every project has one owning workspace and an initial administrator. Validation: a pilot vendor creates a project for a real engagement and confirms no other member sees it uninvited.

## Scope, constraints and exceptions
- One owning workspace per project (BR-001); Scrum only, one team and calendar, at most one active Sprint (BR-027).
- **User-selected (OQ-004-01/02):** the engagement is chosen at creation from engagements the creator can see; it can change only while Draft; it is fixed once Active.
- **User-selected (OQ-004-03/13):** name ≤160, duplicates allowed, purpose required; project-first model with no Product entity in MVP.
- `organization.projects.create` exists in Identity (TASK-DP-003-020); everything inside the project is Projects-owned (ADR-001 D-03).
- Creating a project grants no access to other workspace members (BR-003).
