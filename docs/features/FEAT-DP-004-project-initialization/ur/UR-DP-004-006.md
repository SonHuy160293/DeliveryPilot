# UR-DP-004-006 — Know when a project is initialized and ready for delivery

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Problem and context
LC01 exits when named owners acknowledge obligations and the authorized project owner records readiness. Without an explicit state, teams cannot tell a Draft set-up from a project ready for backlog and Sprint work.

## User need
As a project administrator, I need to mark a Draft project Active once the essentials are in place, so that everyone knows delivery can start.

## Business value and observable outcome
Projects show Draft or Active; the transition is attributable, lists any waiver, and does not imply acceptance of future requirements (LC01 exit).

## Scope, constraints and exceptions
- **User-selected (OQ-004-10):** Draft/Active; required Product Goal, Sprint length, a PM participant and, for client projects, an engagement; a missing client PO can be waived with a reason.
- Project closure belongs to FEAT-DP-030.
