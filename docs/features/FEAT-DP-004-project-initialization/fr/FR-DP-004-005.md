# FR-DP-004-005 — Apply the project role matrix

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall provide the fixed project roles Project Administrator, PM, BA, Developer, QA, DevOps and Viewer, let a participant hold several roles with additive permissions, and apply the matrix below, with guests always excluded from management permissions.

## Preconditions and trigger
A project exists.

## Main behavior
Permission matrix (MVP; backlog and Sprint work permissions are added by FEAT-DP-008/009/011): **read project** — all roles; **edit brief / Product Goal** — Administrator, PM, BA; **edit stakeholders** — Administrator, PM; **edit cadence** — Administrator, PM (members only); **manage participants (add, remove, change non-administrator roles)** — Administrator, PM (members only); **invite and revoke guests** — Administrator, PM (members only); **assign client PO** — Administrator; **initialize project** — Administrator; **grant/remove Project Administrator** — Administrator; **read project change history** — Administrator, PM (members only). Guests may hold any role except Project Administrator and receive only that role's work permissions (read, brief, stakeholders), never cadence, participant, guest, client-PO, initialization, administrator or change-history permissions. Changing non-administrator roles applies to admitted guests as well as members. Project roles grant no workspace permission and workspace roles grant no project permission.

## Validation, business rules and authorization
- **User-selected (OQ-004-04, OQ-004-06 + follow-up).**
- **User-selected (OQ-004-17, 2026-11-10):** direct role changes for admitted guests.
- **User-selected (OQ-004-18, 2026-11-10):** change-history readers; previous Product Goal values and the activation waiver stay visible to every participant.
- BR-005, SCOPE-04, ADR-001 D-03.
- A participant cannot assign Project Administrator unless they are one (BR-006 principle).

## Failure and edge cases
- Participant with zero roles: not allowed; removing the last role removes the participation.
- Unknown role name: rejected.

## Verification criteria
- A Developer cannot manage participants; a member PM can; a guest PM cannot.
- A person holding BA and QA has the union of both permissions.
- A Developer and a guest PM cannot read the project change history; a member PM can.
- A member PM changes an admitted guest from Viewer to BA without a new invitation; granting the guest Project Administrator is rejected.
- Being PM in project X gives no permission in project Y; a workspace Owner who is not a participant has no project permission.

Criteria are scenarios for task planning, not executed tests.
