# FR-DP-004-001 — Create a Scrum project

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let an authorized vendor workspace member create a Scrum project owned by the selected workspace, in Draft state, and make the creator its initial Project Administrator.

## Preconditions and trigger
Authenticated user with a current session and active membership holding `organization.projects.create` in the selected workspace, confirmed with Identity uncached for this command (ADR-001 D-03/D-04).

## Main behavior
Require name (trimmed, 1–160 characters, duplicates allowed) and purpose (trimmed, 1–500 characters). Record owning workspace, creator, UTC creation time, Scrum (fixed, not selectable), Draft state, Sprint length default 2 weeks, and the creator as a participant holding Project Administrator. Optionally associate an engagement (FR-DP-004-002). No other workspace member gains access.

## Validation, business rules and authorization
- BR-001, BR-003, BR-008; Scrum only (BR-027, D7).
- **User-selected (OQ-004-03/13):** naming rules; project-first, no Product entity.
- Project, owner workspace and administrator participation are established atomically (NFR-004).

## Failure and edge cases
- Missing permission, revoked session, removed membership or inactive organization: nothing created.
- Identity unavailable: fail closed.
- Blank or over-length name/purpose: rejected.
- Failure establishing the administrator leaves no project.
- A retried identical request must not create a duplicate (replay design is task-level).

## Verification criteria
- A holder of the create-project permission creates a Draft Scrum project and is its Project Administrator.
- Another member of the same workspace without participation cannot see it.
- A member without the permission is denied and nothing is created; a 161-character name is rejected.

Criteria are scenarios for task planning, not executed tests.
