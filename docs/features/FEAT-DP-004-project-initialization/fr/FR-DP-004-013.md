# FR-DP-004-013 — Delegate project administration and recover an orphaned project

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a Project Administrator grant Project Administrator to another member participant and step down while at least one active administrator remains, and let a workspace Owner appoint a member participant as administrator when the project has no active administrator.

## Preconditions and trigger
Delegation: caller is Project Administrator; target is an active member participant. Recovery: the project has no administrator with active workspace membership; caller is an Owner of the owning workspace (Identity check, uncached).

## Main behavior
Granting and removing the role are attributable. The last active administrator cannot step down or be removed. A project whose administrators have all lost workspace membership is flagged 'no active administrator'. A workspace Owner may then appoint one existing member participant as Project Administrator; the recovery is audited with reason, and the Owner gains no project content access and does not become a participant. If no member participant remains, the project stays flagged.

## Validation, business rules and authorization
- **User-selected (OQ-004-14).**
- Workflow §4.2: the creator initially administers and may delegate.
- Guests can never hold Project Administrator.

## Failure and edge cases
- Two administrators removing each other concurrently: at least one remains.
- Recovery attempted while an active administrator exists: rejected.
- Non-Owner attempting recovery: denied.

## Verification criteria
- After delegation both are administrators and the original can step down.
- The last administrator cannot step down.
- When all administrators left the workspace, an Owner appoints a member participant; the Owner still cannot open project content.

Criteria are scenarios for task planning, not executed tests.
