# FR-DP-004-004 — Configure Scrum cadence

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a Project Administrator or member PM set the project's Sprint length in whole weeks from 1 to 4 (default 2) for its single team and Sprint calendar.

## Preconditions and trigger
A Draft or Active project; caller holds cadence permission per the project role matrix in FR-DP-004-005; guests never hold it.

## Main behavior
Store the Sprint length. A change applies only to Sprints not yet started; Sprint creation, the one-active-Sprint rule and planned-Sprint effects belong to FEAT-DP-009.

## Validation, business rules and authorization
- BR-027, BR-028; **User-selected (OQ-004-12)**.
- Multiple teams per project are deferred.

## Failure and edge cases
- 0 or 5 weeks: rejected.
- Guest PM: denied.

## Verification criteria
- A three-week length is accepted; five weeks is rejected.
- No option offers another delivery framework.

Criteria are scenarios for task planning, not executed tests.

## Open questions
- None blocking for task planning; decisions are recorded in the feature decision record.
