# FR-DP-004-007 — Enforce project visibility

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall show a project and its content only to its participants and admitted guests, within their roles, filtering every read by owning workspace and project; holders of engagement read-all or manage see only the name, status and administrator names of projects under an engagement.

## Preconditions and trigger
Any read of project data.

## Main behavior
Project lists return only projects where the caller participates or is an admitted guest. Direct access to any other project returns not found. Workspace membership, engagement read-all/manage, the engagement's client-PO designation and a client organization link never grant project content access; on the engagement page read-all/manage holders see project name, status and administrator names only (FR-DP-025-006).

## Validation, business rules and authorization
- BR-003, BR-004, BR-008; ADR-001 D-07; NFR-001/002.
- **User-selected (OQ-004-08).**
- Guests need an active guest grant; what they see inside is further limited by role and FEAT-DP-015 sharing.

## Failure and edge cases
- Guessing a project ID in another workspace: not found.
- Revoked guest or removed participant: denied.
- Identity unavailable for vendor members: fail closed.

## Verification criteria
- A workspace member without participation gets not found for the project.
- A guest of project P cannot see project Q in the same workspace.
- A read-all holder sees P's name and status on the engagement page but cannot open P.

Criteria are scenarios for task planning, not executed tests.
