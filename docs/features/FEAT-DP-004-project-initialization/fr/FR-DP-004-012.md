# FR-DP-004-012 — Mark a project initialized

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a Project Administrator move a Draft project to Active once it has a Product Goal, a Sprint length, at least one participant holding PM and, for client projects, an engagement, with a missing client PO allowed only through a recorded waiver reason.

## Preconditions and trigger
Project in Draft; caller is Project Administrator.

## Main behavior
Check the required items and report every gap. For a client project without an assigned client PO, require a waiver reason. Record actor, UTC time and any waiver. Active is readiness, not acceptance of scope or requirements. Active projects cannot return to Draft in MVP.

## Validation, business rules and authorization
- **User-selected (OQ-004-10).**
- LC01 exit (SDLC workflow).
- Project closure is FEAT-DP-030.

## Failure and edge cases
- Any required item missing: rejected with the full list.
- Client PO missing without waiver reason: rejected.
- Already Active: no change.

## Verification criteria
- A complete Draft project becomes Active and records who activated it.
- A Draft project without a Product Goal cannot become Active.
- A client project without client PO becomes Active only with a waiver reason, which is shown afterwards.

Criteria are scenarios for task planning, not executed tests.
