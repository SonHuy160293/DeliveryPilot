# TASK-DP-004-004 — Enforce project access and read projects

## Objective and source contract
Introduce the project access rule and role-matrix evaluation used by every later task, and the project reads: a member's project list, a guest's own project list, project detail and the participant list. ## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Queries open no command transaction and write no event.
- The access evaluator returns the caller's participant, kind and effective project permissions, or signals not-found. It is the single place that implements the rule above and the FR-DP-004-005 matrix.
- For queries the Identity check for a member may be cached for at most 30 seconds (ADR-001 D-04); this task asks uncached and leaves caching as a later optimization.
- Workspace membership, `organization.engagements.read-all`/`manage`, Owner or Admin status, an engagement's client-PO designation and a client organization link grant no project access.
- **Member list:** projects of the route workspace where the caller is an active `Member` participant, after the workspace check.
- **Guest list:** projects where the caller is an active `Guest`, across workspaces, with project ID, owning organization ID, name, status and the caller's roles. No workspace check.
- **Detail:** name, purpose, kind, status, Sprint length, engagement ID and activation waiver reason (members only, FEAT-DP-015 OQ-015-02), client PO participant, activation data, `version`, and the caller's roles and permissions.
- **Participants:** active participants with user ID, kind, roles and display name from Identity's batch lookup; names are never stored. If the lookup fails, the list is returned without names rather than failing.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed):**
  - `GET .../projects?status=&limit=&cursor=` (member list);
  - `GET api/v{version:apiVersion}/me/guest-projects` (guest list);
  - `GET .../projects/{projectId:guid}`;
  - `GET .../projects/{projectId:guid}/participants`.
- **Success:** 200; lists use `limit` and an opaque `cursor`.
- **Errors:** 404 for a project of another workspace or one the caller does not participate in, with the same body as an unknown ID.

## Test matrix
- **Member without participation:** not listed; 404 by ID.
- **Workspace Owner without participation:** 404.
- **Engagement read-all holder:** 404 on the project.
- **Cross-tenant:** project of workspace A requested under workspace B gives 404.
- **Member removed from workspace:** Identity denies; project answers 404 on the next request.
- **Guest:** sees project P in the guest list and by ID, not project Q of the same workspace; never the engagement ID.
- **Matrix:** BA plus QA has the union of permissions; a guest PM has no management permission; a Developer cannot manage participants.
- **Names:** returned from the lookup; lookup failure still returns the list.
- **Fail closed:** Identity unavailable gives 503 for a member.
