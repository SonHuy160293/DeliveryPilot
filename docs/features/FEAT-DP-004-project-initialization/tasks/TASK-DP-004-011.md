# TASK-DP-004-011 — Revoke guests, let guests leave and change guest roles

## Objective and source contract
Let a Project Administrator or member PM revoke a guest or change an admitted guest's roles, and let a guest leave, ending access while keeping attribution. Sources: [FR-DP-004-005](../fr/FR-DP-004-005.md), [FR-DP-004-010](../fr/FR-DP-004-010.md); [US-DP-004-008](../us/US-DP-004-008.md) AC-001, AC-003 and AC-004; OQ-004-17. ## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- **Revoke:** permission invite-and-revoke-guests; target must be an active `Guest`; status `Revoked`, grants revoked, optional reason. Revoking an already ended guest changes nothing.
- **Leave:** only the guest themself; status `Left`. Members do not leave through this route.
- **Client PO:** when the ended guest is the project's client PO, `ClientProductOwnerParticipantId` and its assignment columns are cleared in the same transaction and `client-po.cleared` is recorded.
- **Change guest roles:** same permission as managing participants; any non-empty set of roles except `ProjectAdministrator`; applied directly without a new invitation (OQ-004-17). An empty set is rejected: use revoke.
- Access ends on the next request; a guest's in-flight command fails its participation recheck before commit.
- Earlier decisions and actions keep the guest as actor.
- Events `guest.revoked`, `guest.left`, `participant.roles-changed`.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed):**
  - `POST .../projects/{projectId:guid}/guests/{participantId:guid}/revoke` (`expectedVersion`, `reason`);
  - `PUT .../guests/{participantId:guid}/roles` (`expectedVersion`, `roles`, `reason`);
  - `POST .../projects/{projectId:guid}/leave` (guest only).
- **Errors:** 400 empty roles or `ProjectAdministrator`; 403 guest PM or missing permission, or a member calling leave; 404 participant not in project or not a guest; 409 stale version.

## Test matrix
- **Revoke:** the guest is denied on the next request; their earlier events still show them as actor.
- **Client PO:** revoking or leaving as client PO leaves the project without one and records the clearing.
- **Leave:** the guest no longer sees the project.
- **Role change:** Viewer to BA without a new invitation; `ProjectAdministrator` rejected.
- **In-flight:** a guest command racing with revocation does not commit after it.
- **Permissions:** guest PM cannot revoke; a member cannot use leave.
