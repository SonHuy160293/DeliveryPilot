## Behavior and invariants
- Schema `project`; plural PascalCase tables, PascalCase columns, quoted identifiers; UUIDv7 IDs; UTC instants; `date` for calendar dates.
- Every table carries `OrganizationId`; project children also carry `ProjectId`. `Projects` exposes `(OrganizationId, Id)`; `ProjectParticipants` and `ProjectGuestInvitations` expose `(OrganizationId, ProjectId, Id)`. Children reference parents with composite foreign keys, so a row cannot point into another tenant or another project.
- `Projects.ClientProductOwnerParticipantId` uses the foreign key `(OrganizationId, Id, ClientProductOwnerParticipantId)` to `ProjectParticipants (OrganizationId, ProjectId, Id)`; the circular reference with participants needs a deferred or nullable-first insert order.
- Database constraints from the ERD:
  - checks: `Kind = 'Client' OR EngagementId IS NULL`; status and kind codes; `SprintLengthWeeks` 1–4; role codes; `OfferedRoleCode` never `ProjectAdministrator`; invitation `ExpiresAt = LastIssuedAt + 7 days`; paired `...At`/`...ByUserId` columns;
  - unique `(OrganizationId, ProjectId, UserId)` on participants;
  - partial unique `(OrganizationId, ParticipantId, RoleCode)` where `RevokedAt IS NULL`;
  - partial unique `(OrganizationId, ProjectId, RecipientEmail)` where `Status = 'Pending'`.
- `Version` concurrency tokens on `Projects`, `ProjectBriefs`, `ProjectParticipants`, `ProjectGuestInvitations`, `ProjectGuestInvitationDeliveries`, `ProjectStakeholders`.
- `ProjectEvents` is append-only in application code.
- Role catalog in code (PRJ-14): `ProjectAdministrator`, `ProjectManager`, `BusinessAnalyst`, `Developer`, `QualityAssurance`, `DevOps`, `Viewer`, with the FR-DP-004-005 permission matrix as data that [TASK-DP-004-004](TASK-DP-004-004.md) evaluates.
- Physical types, lengths and index names are decided here (PRJ-16).

## Persistence, events and integrations
- One migration after the engagement migration. Indexes implied by the ERD: `(OrganizationId, EngagementId)`; `(OrganizationId, Status, CreatedAt, Id)`; `(OrganizationId, UserId, Status)` on participants plus one that serves a guest's own list by `UserId`; `(OrganizationId, ProjectId, RoleCode)` filtered `RevokedAt IS NULL`; delivery indexes for issuance limits; `(OrganizationId, ProjectId, OccurredAt, Id)` on events.
- No cross-module foreign keys: every `...UserId` and `OrganizationId` is a scalar Identity ID.

## Test matrix
- **Model:** schemas are `engagement`, `project` and `reliability`; every `project` table has `OrganizationId`.
- **PostgreSQL:** migrations apply to an empty database and leave none pending.
- **Tenant and project isolation:** a participant, role, invitation, delivery, stakeholder or event pointing at another tenant's or another project's parent fails; a client PO from another project fails; a project pointing at another tenant's engagement fails.
- **Constraints:** internal project with an engagement, Sprint length 0 and 5, duplicate active role, second pending invitation for one email, an invitation offering `ProjectAdministrator`, and a second participant row for one user each fail.
- **Concurrency:** stale `Version` on project and on brief each raise `DbUpdateConcurrencyException` independently.
