# TASK-DP-004-003 — Create a Scrum project

## Objective and source contract
Let a holder of `organization.projects.create` create a Draft Scrum project, client (under an Active engagement) or internal, becoming its first Project Administrator. ## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- This command is a workspace entry point, not a project action: authority is `IWorkspaceAuthority.RequireAsync` with `organization.projects.create`, uncached. The project access rule above applies only to later requests.
- Required: name (trimmed, 1–160, duplicates allowed) and purpose (trimmed, 1–500). `kind` is `Client` or `Internal`.
- A client project may name an engagement. It must be in the same workspace, `Active`, and visible to the creator with full detail (read-all, manage, or engagement creator). Not visible or another workspace gives 404; Closed gives 409 `Engagement.Closed`. An internal project with an engagement is rejected.
- Creation locks the engagement row `FOR SHARE` so it cannot close concurrently (ERD invariants); with a concurrent close, exactly one of the two outcomes wins.
- In one transaction: the project (`Draft`, Scrum fixed, `SprintLengthWeeks = 2`), its empty `ProjectBriefs` row, the creator's participant row (`Member`, `Active`) and a `ProjectAdministrator` role grant. A failure in any step leaves nothing.
- Idempotency as in TASK-DP-025-002: operation `project.create`, `Idempotency-Key` header, replay returns the same project.
- No other workspace member gains access.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Method and route (proposed):** `POST .../projects` with required GUID `Idempotency-Key`.
- **Body:** `name`, `purpose`, `kind` (required); `engagementId` (optional, client only).
- **Success:** 201 (200 on replay) with `id`, `status`, `kind`, `engagementId`, `sprintLengthWeeks`, `version`.
- **Errors:** 400 blank or over-length name or purpose, or an engagement on an internal project; 403 without the create code; 404 engagement not visible; 409 Closed engagement or key reuse.

## Test matrix
- **Client project:** created under an Active visible engagement, Draft, two-week Sprint length, creator is administrator, brief row exists, one event.
- **Internal project:** created without engagement; with an engagement gives 400.
- **Engagement not visible / other workspace:** 404, nothing created. **Closed:** 409.
- **Race:** concurrent close and create never leave a new project under a Closed engagement.
- **Close keeps existing projects (deferred from TASK-DP-025-008, US-DP-025-007 AC-001):** closing an engagement that has an Active project succeeds and leaves the project's status, engagement link and participants unchanged.
- **Authorization:** no create code gives 403; Identity unavailable gives 503.
- **Invalid:** 161-character name, blank purpose: 400.
- **Atomicity:** a forced failure after the project insert leaves no project, brief, participant or grant.
- **Idempotency:** replay returns the same ID; different body with the same key gives 409.
