# TASK-DP-004-015 — Flag projects without an active administrator and let an Owner recover them

## Objective and source contract
Show when a project has no administrator who is still a workspace member, and let a workspace Owner appoint an existing member participant as Project Administrator without gaining project access. Sources: [FR-DP-004-013](../fr/FR-DP-004-013.md); [US-DP-004-012](../us/US-DP-004-012.md) AC-003; OQ-004-09/14; PRJ-15. All source UR/FR/US are `ready` with `approval_ref: null`: complete for planning, not client-approved.

## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- **Flag (PRJ-15):** computed at read time: the project is flagged when none of its active `ProjectAdministrator` holders is an active workspace member according to Identity's batch membership check. It is added to the project detail for member participants; guests do not see it (FEAT-DP-015 OQ-015-02).
- **Owner view:** a workspace Owner (`IWorkspaceAuthority`, `IsOwner`, uncached) lists flagged projects of the workspace with project ID, name and status only, and for one flagged project the member participants who are still workspace members (user ID and display name when the lookup is available). No project content.
- **Recovery:** the Owner appoints one of those participants as `ProjectAdministrator` with a required reason. Preconditions are rechecked under the project row lock: still no active administrator with workspace membership, and the appointee is an active `Member` participant and an active workspace member.
- The Owner does not become a participant and still gets 404 on the project itself.
- If no eligible participant remains, the project stays flagged and recovery is rejected.
- Event `administration.recovered` with `ActorUserId` = the Owner, the appointee and the reason.
- Identity unavailable gives 503; the flag is never shown as false on a failed check.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed):**
  - `GET .../organizations/{organizationId:guid}/project-recovery` (flagged projects);
  - `GET .../project-recovery/{projectId:guid}/candidates`;
  - `POST .../project-recovery/{projectId:guid}/appoint` (`participantId`, `reason`).
- **Errors:** 400 missing reason; 403 caller is not an Owner; 404 project not in workspace; 409 an active administrator exists, or the candidate is not eligible.

## Persistence, events and integrations

## Test matrix
- **Flag:** set when all administrators lost workspace membership; not set while one remains.
- **Recovery:** the Owner appoints Bob with a reason; Bob administers; the event is recorded; the Owner still gets 404 on the project.
- **Active administrator exists:** recovery rejected.
- **Non-Owner (Admin, member):** 403.
- **Guest or non-member candidate:** rejected.
- **No candidate:** project stays flagged.
- **Fail closed:** Identity unavailable gives 503.
