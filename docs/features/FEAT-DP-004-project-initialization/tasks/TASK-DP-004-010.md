# TASK-DP-004-010 — Preview, accept and decline a project guest invitation

## Objective and source contract

## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- These routes are not workspace-scoped and do not use the project access rule: the caller is an authenticated user holding the invitation ID and proof.
- **One generic failure** (`ProjectInvitation.Unavailable`, 404 proposed) for an unknown invitation, wrong proof, rotated proof, expired, cancelled, declined or already accepted invitation, and an email mismatch, so nothing about the invitation leaks.
- **Checks at acceptance, in order, inside the transaction with the project row locked:**
  1. invitation `Pending`, not expired, proof matches the verifier;
  2. Identity email match for the caller and the invitation email (PRJ-19);
  3. the inviter (`IssuedByUserId`) is still an active workspace member (batch membership check) and still an active project participant with guest permission; otherwise no grant, and a current authorized user must reissue;
  4. the caller is not an active member of the owning workspace; if they are, 409 `ProjectInvitation.MemberMustBeParticipant` with guidance to be added as a participant.
- **Admission:** create or reactivate the participant row as `Guest` with the offered role, set `AdmittedViaInvitationId`, mark the invitation `Accepted`. If the caller already is an active guest, no duplicate is created and the invitation is closed.
- **Former member (OQ-004-15):** if the caller has an active `Member` participation but is no longer a workspace member, acceptance ends it (`Removed`, roles revoked, event recorded) and reactivates the same row as `Guest` with the offered role, in the same transaction.
- **Decline:** status `Declined`; nothing else changes. **Expiry** creates nothing.
- Events `invitation.accepted`, `invitation.declined`, `participant.added` or `participant.reactivated`, and `participant.removed` for a conversion; never the proof.
- Identity unavailable gives 503 and no grant.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed, mirroring Identity's `organization-invitations/{invitationId}`):** `POST api/v{version:apiVersion}/project-invitations/{invitationId:guid}/preview`, `.../accept`, `.../decline`.
- **Body:** `proof` (required); `expectedVersion` for accept and decline.
- **Preview:** project name, offered role and expiry only.
- **Success:** 200; accept returns the project ID and owning organization ID.
- **Errors:** 404 generic failure; 409 member-must-be-participant or stale version; 503 Identity unavailable.

## Test matrix
- **Accept:** matching account becomes a guest with the offered role, sees only that project, and is absent from Identity's member list (no Identity write happens).
- **Wrong account:** another signed-in user gets the generic failure and no grant.
- **Expired:** an invitation issued 8 days ago gives the generic failure.
- **Rotated:** the proof from before a resend fails.
- **Inviter lost permission or membership:** no grant.
- **Workspace member:** 409 with guidance, no grant.
- **Already a guest:** no duplicate row.
- **Former member:** leftover member participation ends and the row becomes a guest with only the offered role.
- **Decline:** invitation closed, no participation.
- **Single use:** two parallel accepts create one participation.
- **Fail closed:** Identity unavailable gives 503.
