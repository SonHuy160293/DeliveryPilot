# TASK-DP-004-014 — Mark a project initialized

## Objective and source contract
Let a Project Administrator move a Draft project to Active once the essentials exist, reporting every gap and recording a waiver when the client PO is missing. Sources: [FR-DP-004-012](../fr/FR-DP-004-012.md); [US-DP-004-011](../us/US-DP-004-011.md); OQ-004-10. All source UR/FR/US are `ready` with `approval_ref: null`: complete for planning, not client-approved.

## Codebase evidence

- The `engagement` context is being implemented under TASK-DP-025-001 (in progress, uncommitted): `DeliveryPilot.Projects.Domain/Models/Engagements/`, `Infrastructure/Persistence/Configurations/Engagement*Configuration.cs`, migration `20261110035531_AddEngagementPersistence`, tests `Persistence/EngagementModelTests`, `Persistence/EngagementPostgreSqlTests` and `Support/ProjectsPostgreSqlCollection`. - Bearer authentication already confirms the session with Identity on every request (`IdentitySessionValidator`), for members and guests alike.
- Tests live in `tests/DeliveryPilot.Projects.Tests` (`FakeIdentityAuthorityClient`, `PostgreSqlFactAttribute` on `DELIVERYPILOT_TEST_PROJECTS_POSTGRES`).

## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- Permission: initialize (Project Administrator only).
- Required: a non-empty Product Goal; a Sprint length; at least one active participant holding `ProjectManager`; for a client project, an engagement.
- For a client project without an assigned client PO, a non-blank waiver reason (≤2000) is required and stored in `ClientPoWaiverReason`. Internal projects need no client PO.
- All gaps are evaluated and returned together; the command changes nothing when any is present.
- On success: `Status = Active`, `ActivatedAt`, `ActivatedByUserId`, one `project.activated` event with the waiver reason when given. The checks run under the project row lock so the facts cannot change between check and commit.
- An already Active project is returned unchanged with no event. Active never returns to Draft.
- Active means ready to start, not acceptance of scope.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed):** `GET .../projects/{projectId:guid}/readiness`; `POST .../projects/{projectId:guid}/initialize` (`expectedVersion`, `clientPoWaiverReason`).
- **Success:** 200 with status and activation data; readiness returns the list of missing items.
- **Errors:** 403 non-administrator; 409 `Project.NotReady` with every missing item in the error details, or stale version.

## Test matrix
- **Complete client project:** becomes Active with actor and UTC time.
- **Missing Product Goal:** rejected, and the response lists every missing item, not just the first.
- **Waiver:** a client project without a client PO activates only with a reason, which the project detail then shows.
- **Client project without engagement:** rejected. **Internal project:** activates without engagement or client PO.
- **No PM:** rejected.
- **Already Active:** no change, no event.
- **Permissions:** member PM gets 403.
