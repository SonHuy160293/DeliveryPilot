# TASK-DP-004-006 — Configure Sprint length and change a Draft project's engagement or kind

## Objective and source contract
Let a Project Administrator or member PM set the Sprint length, and let an eligible Project Administrator change a Draft project's engagement or switch it between client and internal. Sources: [FR-DP-004-002](../fr/FR-DP-004-002.md), [FR-DP-004-004](../fr/FR-DP-004-004.md); OQ-004-01/02/12/16. All source UR/FR/US are `ready` with `approval_ref: null`: complete for planning, not client-approved.

## Scope and dependencies
**In scope:** Sprint-length command; engagement set/change/remove; client/internal switch.

**Out of scope:** Sprint creation and the effect on planned Sprints (FEAT-DP-009).

**Depends on:** [TASK-DP-004-004](TASK-DP-004-004.md).

## Behavior and invariants
- **Project access rule (defined in [TASK-DP-004-004](TASK-DP-004-004.md), reused here):** the caller needs an `Active` participant row for `(OrganizationId, ProjectId, UserId)`; otherwise 404. A `Member` participant must also pass `IWorkspaceAuthority.RequireAsync` for the workspace, uncached for commands; a denial is answered 404 and Identity being unavailable 503. A `Guest` needs no workspace membership. Permissions are the union of the caller's active roles under the FR-DP-004-005 matrix; guests never get cadence, participant, guest, client-PO, initialization or administrator permissions. A participant who lacks the needed permission gets 403.
- Commands check access and the required permission first, then lock the `Projects` row `FOR UPDATE` and recheck the caller's participation inside the transaction, so a concurrent removal or revocation wins (FR-DP-004-010).
- Every accepted change appends exactly one `project.ProjectEvents` row in the same transaction with actor, acting organization, UTC time, reason, `Details` (previous and new values) and the resulting `ProjectVersion`. A request that changes nothing appends no event.
- Stale `expectedVersion` gives 409 and no change. The pipeline transaction commits.
- **Sprint length:** whole weeks 1–4; Draft or Active projects; permission cadence (Administrator or member PM; never a guest). Event `project.cadence-changed`. The value applies to Sprints not yet started, which FEAT-DP-009 implements.
- **Engagement and kind:** only while `Draft`; the caller must be a Project Administrator **and** hold `organization.engagements.manage` (checked with `IWorkspaceAuthority`, uncached). A reason is required.
- Setting or changing the engagement requires it to be in the same workspace, `Active` and visible to the caller with full detail; the engagement row is locked `FOR SHARE`. Removing it leaves a client project without an engagement, which is valid while Draft.
- Switching to `Internal` clears the engagement in the same transaction; switching to `Client` may name an engagement in the same request.
- On an Active project every engagement or kind change gives 409 `Project.NotDraft`.
- Events `project.engagement-changed` and `project.kind-changed`.

## API contract (only for API tasks)
- **Route base (proposed):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/projects`. Not exposed through the Gateway until TASK-DP-004-017.
- **Authentication and tenant:** `[Authorize]`; user and session from `ICurrentUserProvider`; the workspace is the route `organizationId` and every query filters by it first (ADR-001 D-07).
- **Errors:** 400 validation; 401; 403 participant without the permission; 404 project of another workspace or caller not an active participant (same response); 409 conflict; 503 Identity unavailable.
- **Routes (proposed):** `PUT .../projects/{projectId:guid}/sprint-length`; `PUT .../projects/{projectId:guid}/engagement`.
- **Bodies:** sprint length: `expectedVersion`, `sprintLengthWeeks`. Engagement: `expectedVersion`, `kind`, `engagementId` (nullable), `reason` (required).
- **Errors:** 400 for 0 or 5 weeks, a missing reason or an engagement on an internal project; 403 guest PM, non-administrator, or administrator without the manage code; 404 engagement not visible; 409 Closed engagement, Active project or stale version.

## Test matrix
- **Cadence:** three weeks accepted; five rejected; a guest PM gets 403; a member PM succeeds.
- **Engagement change:** Draft project moved to another Active engagement with a reason; without the manage code 403; engagement in another workspace 404; Closed 409.
- **Kind switch:** client to internal clears the engagement; internal to client with an engagement succeeds.
- **Active project:** every change gives 409.
- **Race:** concurrent engagement close and move never leave the project under a Closed engagement.
