# US-DP-004-011 — Mark the project initialized

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Story
As a project administrator, I want to mark the project Active when the essentials are present, so that the team knows delivery can start.

## Context and boundaries
LC01 exit; not scope approval.

## Acceptance criteria
### AC-001 — Initialize
**Given** a Draft client project with Product Goal, Sprint length, a PM, an engagement and a client PO **When** I mark it Active **Then** it becomes Active and records me and the UTC time.

### AC-002 — Missing items
**Given** a Draft project without a Product Goal **When** I try to activate it **Then** the request is rejected and lists the missing items.

### AC-003 — Waived client PO
**Given** a Draft client project complete except the client PO **When** I activate it with a waiver reason **Then** it becomes Active and the waiver is shown.
