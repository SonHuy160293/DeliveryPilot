# US-DP-004-001 — Create a client Scrum project under an engagement

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Story
As a vendor PM with the create-project permission, I want to create a Scrum project under a client engagement, so that delivery starts in the right commercial context.

## Context and boundaries
VS-02 step 2. Depends on FEAT-DP-025 US-DP-025-001 (cross-feature, not expressible in `depends_on`).

## Acceptance criteria
### AC-001 — Create under engagement
**Given** I hold `organization.projects.create` and can see Active engagement E in workspace A with full detail **When** I create project P under E with a name and purpose **Then** P is a Draft Scrum project under E with a two-week Sprint length, owned by A, and I am its Project Administrator.

### AC-002 — Engagement not visible
**Given** engagement E exists but I hold neither read-all nor manage and did not create it **When** I try to create a project under E **Then** the request fails as not found.

### AC-003 — Closed engagement
**Given** engagement E is Closed **When** I try to create a project under E **Then** the request is rejected.

### AC-004 — No permission
**Given** I lack the create-project permission **When** I try to create a project **Then** nothing is created.
