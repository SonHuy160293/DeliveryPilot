# UR-DP-002-003 — End authenticated access with clear scope

## Problem and context
A user leaving a shared or personal device needs confidence that the authenticated context they ended cannot continue to access protected work. Clearing a screen without ending the relevant access leaves an ambiguous security outcome.

## User need
As an authenticated platform user, I need to end my authenticated access and understand which context was ended so that another person cannot continue using that access.

## Business value and observable outcome
After logout is confirmed, protected operations relying on the ended context require authentication again. Repeating logout is safe. Validate the outcome on a shared-device scenario and with concurrent requests.

## Scope, constraints and exceptions
Logout is distinct from deleting an account, removing membership or reversing completed approvals. Which other devices or sessions are affected is an explicit open policy choice (D-006). Preserve historical actor attribution while applying privacy controls (NFR-003, NFR-008).

## Evidence and validation
The roadmap explicitly includes login and logout. Internal need-level review confirms the actor, outcome and resource/privacy boundaries. Registration uses email/password and does not issue a JWT; detailed session and logout behavior remains in separate draft FRs. This review is not authorization to implement those flows.

## Open questions
Functional details such as session duration, refresh, logout scope and post-login navigation are deferred to the associated FR/US review. They do not alter this user need or authorize their implementation.


## Readiness review — 2026-11-02
Reviewed for internal completeness against the confirmed registration phase and applicable global constraints. User clarification and subsequent confirmation in this conversation resolve public self-registration, immediate activation, no email verification and no automatic login.
