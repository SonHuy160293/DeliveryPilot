In scope: credential lookup and verification (with dummy PBKDF2 timing equalization), `User.LastLoginAt` update + `IAuthSessionService.CreateAsync` in the command transaction, login command/validator/handler/response, API-local `LoginUserRequest`, `Set-Cookie: dp_refresh_token` and `Cache-Control: no-store` response headers, exact Gateway publication (`POST /identity/api/v1/auth/login`), safe diagnostics, atomicity and regression tests.

Out of scope: login UI, arbitrary redirect destinations, organization/project selection APIs, grants, approvals, recovery, federation/MFA, and logout/refresh HTTP endpoints. ## Behavior and invariants
1. Validate before starting the command transaction. Supported proof is email and password (`FR-DP-002-003`). Trim email, preserve `Password` byte-for-byte as a string, and apply the same canonical identity equivalence (`lower("PrimaryEmail")`) as registration/PostgreSQL. Do not reuse `ExistsForRegistrationAsync` or serialize login attempts behind registration's advisory lock.
2. Fetch the server-owned identity and protected verifier through an Application-owned repository abstraction. Verify with `PasswordHasher`&lt;`User`&gt;, treating `PasswordVerificationResult.Success` and `PasswordVerificationResult.SuccessRehashNeeded` as valid proof without mutating `PasswordCredentials`. When the email or credential does not exist, execute a dummy `VerifyHashedPassword` against a precomputed dummy hash so missing-identity attempts pay the same PBKDF2 work factor. Catch malformed/corrupt stored hash exceptions inside `PasswordHashService` and return false without logging the hash or password.
3. Only `Status == "active"` accounts are eligible, including registered accounts with null `EmailVerifiedAt`. `pending`, `suspended`, `deleted` or missing-credential identities cannot authenticate. No activation, verification or new account is created by login.
4. Unknown email, incorrect password, missing credential, and inactive accounts establish no context, perform no mutation, and return `401 Unauthorized` with code `Authentication.InvalidCredentials` and message `"Invalid email or password."`.
5. For an eligible user with valid proof, update `User.LastLoginAt` (UTC via `TimeProvider.GetUtcNow()`) and call `IAuthSessionService.CreateAsync(user.Id, cancellationToken)` in the same pipeline-owned command transaction. If `CreateAsync` returns `null` (e.g., concurrent account status change to non-active) or commit fails, roll back both `LastLoginAt` and `AuthSession` and do not return a token or cookie.
6. Repeated or concurrent logins create separate valid `AuthSession` records per the reviewed simultaneous-session policy (no session-count limit). Retry never resets credentials, reactivates an account or elevates privileges.
7. Secrets (raw password, password hash, access JWT, refresh token) stay out of `LoginUserRequest.ToString()`, `LoginUserCommand.ToString()`, `LoginUserResult.ToString()`, validation text, provider exceptions, HTTP logs and failure envelopes. Unknown/failed proof is never recorded as an authenticated actor.

## API contract (reviewed and confirmed)
- **Identity:** `POST /api/v1/auth/login` on `AuthController` (`PublicApiController`), `[RequestSizeLimit(16384)]`.
- **Gateway:** `POST /identity/api/v1/auth/login`, exact allowlist to the existing Identity cluster; remove `/identity` prefix; 16,384-byte request body limit and 30-second timeout matching registration. Preserve registration and Notification routes.
- **Authorization:** Anonymous credential submission, with no integration key or prior bearer token required. Existing Users integration protection stays intact. A supplied unrelated/invalid bearer credential cannot choose the login identity.
- **Headers:** `Content-Type: application/json`; optional existing `X-Correlation-Id`. Production HTTPS, trusted forwarding and configured CORS allowlists remain enforced.
- **Request (`LoginUserRequest` under `Identity.API/Contracts/Auth`):** Closed JSON object (`[JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]`) with `email` and `password` only; reject unknown fields including `userId`, `role`, `status`, `tenantId` and `returnUrl`. Null/missing fields fail validation.

| Field | Confirmed validation |
|---|---|
| `email` | Required string, trim, syntactically valid email (same rules as `RegisterUserValidator`), 3–320 characters after trimming; canonical lookup uses `User.NormalizeEmail` / `lower("PrimaryEmail")`. |
| `password` | Required nonempty/non-whitespace string, 1–1024 characters, never trimmed or echoed. |

- **Success response (`200 OK`):**
  - Header `Cache-Control: no-store` (and `Pragma: no-cache`).
  - Header `Set-Cookie` sets `dp_refresh_token` to the URL-encoded refresh token, formats `Expires` from `RefreshTokenExpiresAt` using RFC 1123, and includes `Path=/; Secure; SameSite=Strict; HttpOnly`.
  - Body wrapped in `ApiResponse`&lt;`LoginUserResponse`&gt;:
    - `userId`: `Guid`
    - `accessToken`: `string`
    - `tokenType`: `"Bearer"`
    - `expiresAt`: `DateTimeOffset` (UTC `AccessTokenExpiresAt` from `IssuedAuthSession`)

~~~json
{"email":"alice@example.test","password":"example proof supplied privately"}
~~~

~~~json
{"success":true,"data":{"userId":"019a0000-0000-7000-8000-000000000001","accessToken":"example-signed-access-token","tokenType":"Bearer","expiresAt":"2026-11-02T12:00:00+00:00"},"error":null}
~~~

| Outcome | Confirmed status / response |
|---|---|
| Missing/invalid fields, malformed JSON/type, unknown fields | `400 Bad Request` through existing validation/model-binding envelope, no token, no cookie, and no database writes. |
| Unknown identity, invalid proof, missing credential, or inactive account | `401 Unauthorized` with code `Authentication.InvalidCredentials` and message `"Invalid email or password."`. Never return `userId`, account status, token or cookie. |
| Oversized / unsupported content | `413 Payload Too Large` / `415 Unsupported Media Type` using established transport envelopes. |
| Dependency/signing/persistence failure | Safe existing `500 Internal Server Error` envelope; never return a success fallback, cookie, or provider/password/token details. |
| Gateway forwarding failure | Existing Gateway error/correlation/CORS behavior; login response is not rewritten into success. |

If `CreateAsync` returns `null`, throw `new UnauthorizedException("Authentication.InvalidCredentials", "Invalid email or password.")` so the transaction rolls back `LastLoginAt`.
- No new database migration is needed because `shared.Users.LastLoginAt`, `shared.PasswordCredentials`, and `shared.AuthSessions` already exist.
