# US-DP-002-002 — Log in under the correct identity and permitted scope

## Story
As a returning platform user, I want to sign in under my own identity so that I can continue work within my authorized scope.

## Context and boundaries
An active user signs in with email and password; email verification is not required. Login supplies verified identity, not tenant membership or client approval authority. For a user without membership, the client chooses the onboarding step. NFR-001/NFR-002/NFR-008 apply to both agency users and external collaborators.

## Acceptance criteria
### AC-001 — Eligible user signs in
**Given** an active account and valid email/password, **When** the user logs in, **Then** an authenticated context is established for that identity only, without requiring email verification or creating resource grants; the client chooses the next workspace/onboarding step.

### AC-002 — Invalid proof or ineligible account
**Given** an unknown email, incorrect password or inactive account, **When** login is attempted, **Then** no authenticated context is established and the same message, "Invalid email or password.", is returned without revealing the reason.

### AC-003 — Expired or ended context
**Given** an authentication context that has expired or been ended under the reviewed policy, **When** a protected request or continuation is attempted with it, **Then** it is denied without a protected mutation and authentication is required again.

### AC-004 — Authentication does not confer a resource grant
**Given** a valid authenticated context without access to a tenant/project/artifact, **When** the user changes a resource identifier, supplies a TenantId or attempts an approval, **Then** access is denied by the applicable scope policy rather than granted by login.

### AC-005 — Dependency failure and deferred abuse controls
**Given** an authentication dependency failure, **When** login is attempted, **Then** safe failure feedback is returned and no claimed identity is accepted as a fallback. The user deferred login rate limiting and lockout for this initial phase.

### AC-006 — Private, attributable outcome
**Given** a login succeeds or fails, **When** feedback or diagnostics are produced, **Then** raw passwords and reusable session credentials are not exposed outside the intended successful token-delivery channels, and any recorded actor is not falsely treated as authenticated. The user deferred durable login security-event storage for this initial phase.

## Dependencies and testing notes
Verify validity time boundaries using the selected token policy, dependency outages and missing-membership cases. FEAT-DP-003/FEAT-DP-004 own resource onboarding; FEAT-DP-007 owns approver authority. The user's initial-phase rate-limit and durable-event deferrals do not remove secret protection or safe-failure requirements.
