# US-DP-002-003 — Log out with an enforceable access boundary

## Story
As an authenticated platform user, I want to log out with a clear affected scope so that the access I ended cannot be reused for new protected work.

## Context and boundaries
The user selected ending the current session only: its refresh token is revoked and already-issued access tokens are immediately rejected. Other sessions remain unaffected; already-admitted requests may finish under the general policy. Organization guarded writes additionally obey TASK-DP-003-018 commit ordering; this is a feature-specific qualification, not a new logout endpoint or a resolution of refresh/logout races. Detailed refresh/logout race and failure boundaries still need review. Logout is not account deletion, membership removal or withdrawal of historical approval decisions.

## Acceptance criteria
### AC-001 — Confirmed logout ends access
**Given** a valid context in the logout scope selected by the reviewed policy, **When** the user requests logout and completion is confirmed, **Then** the affected scope is explained and later protected requests relying solely on that ended context require authentication again.

### AC-002 — Repeated logout is safe
**Given** the selected context is already ended, **When** logout is repeated, **Then** no access is restored, no unrelated identity/resource is changed and the reviewed safe outcome is returned.

### AC-003 — Continuation cannot revive ended access
**Given** logout and any supported continuation or protected request occur concurrently, **When** logout is confirmed at the reviewed completion boundary, **Then** new requests/continuations relying on the ended context cannot obtain protected access; requests already admitted follow the explicitly reviewed race policy.

### AC-004 — Prevent cross-user logout
**Given** a user attempts to supply another user's identity/context as a logout target, **When** logout is evaluated, **Then** the unauthorized target is not changed and no context secrets are disclosed.

### AC-005 — Logout cannot be confirmed
**Given** a failure prevents the reviewed completion condition, **When** logout is attempted, **Then** the system does not claim completion, explains a safe next step and does not leak reusable authentication proof.

### AC-006 — Preserve distinct scopes and history
**Given** the user has other contexts, memberships and past approval records, **When** the reviewed logout scope is ended, **Then** other contexts follow that explicit policy while identity, membership and past approval attribution are not deleted by logout.

## Dependencies and testing notes
Resolve D-004, D-006 and D-007 before fixing time/race assertions. Exercise replay, repeated logout, concurrent continuation, two-user isolation and interrupted completion. Approval decision lifecycle remains FEAT-DP-007's responsibility; no approval draft or coding task is created here.
