# FR-DP-002-008 — Protect authentication secrets

## Requirement statement
The system shall protect raw authentication secrets and reusable access proof from unauthorized storage, feedback and diagnostics.

## Preconditions and trigger
Any supported registration, login, session-validity or logout operation handles user information or produces feedback, logs or security evidence.

## Main behavior
Store only a protected password verifier for registration; do not store raw passwords. Keep raw passwords out of responses, errors, logs and diagnostic ToString output. Return reusable access proof only through the intended successful login/refresh delivery channels described by FR-DP-002-005; keep it out of error responses, logs and diagnostic output. Durable security-evidence events, reviewer access and retention are explicitly deferred for this phase.

## Validation, business rules and authorization
NFR-008 is mandatory. Shared privacy safeguards apply to all three user needs without inventing another technical story. No audit database/table, reader policy or retention subsystem is required by initial registration.

## Failure and edge cases
Protect failed attempts, exceptions, duplicate feedback and dependency failures as well as success. Unknown-user failures must not fabricate an authenticated actor. Historical approval attribution remains owned by FEAT-DP-007 and is not removed by logout.

## Verification criteria
- Registration stores only the protected verifier and never returns or logs the password.
- Failure/diagnostic paths do not expose credentials or unrelated private account details.
- Logout does not delete historical business attribution; detailed logout remains separately specified.

## Open questions
No blocker for registration confidentiality. Durable evidence/access/retention decisions remain deferred.
