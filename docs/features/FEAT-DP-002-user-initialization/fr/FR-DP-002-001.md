# FR-DP-002-001 — Register an eligible platform user

## Requirement statement
The system shall permit anonymous self-registration with required DisplayName, Email and Password, creating an active platform user and protected password verifier atomically.

## Preconditions and trigger
An anonymous applicant submits the three required fields. No invitation, tenant identity or existing session is required.

## Main behavior
Trim DisplayName and Email; use consistent case-insensitive email identity matching. A valid submission durably creates one active identity and protected credential, then returns Created with userId. EmailVerifiedAt and LastLoginAt remain null. Do not issue tokens, automatically log in, send verification messages or grant resource access.

## Validation, business rules and authorization
DisplayName must be nonblank and at most 160 characters after trimming. Email must be syntactically valid and 3–320 characters after trimming, compatible with the existing lower(PrimaryEmail) unique index. Password is required and never trimmed or logged. No additional complexity policy is introduced in this phase. FR-DP-002-007 preserves resource boundaries.

## Failure and edge cases
Invalid input or persistence failure must not leave a usable partial registration. Duplicate behavior follows FR-DP-002-002. No success is reported before the transaction commits.

## Verification criteria
- Valid anonymous input creates exactly one active User and one protected credential and returns Created/userId.
- Invalid input or failed persistence creates neither usable partial identity nor authentication.
- Email is not marked verified, no automatic login occurs, and no resource authority is granted.

## Open questions
None blocking this phase. Abuse controls and durable evidence/retention were explicitly deferred by the user.
