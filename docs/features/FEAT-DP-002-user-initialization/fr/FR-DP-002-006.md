# FR-DP-002-006 — End the reviewed logout scope safely

## Requirement statement
The system shall end the authentication context selected by the reviewed logout policy and confirm logout only when that policy's completion condition is satisfied.

## Preconditions and trigger
An authenticated user requests logout, or repeats logout for a context already ended. The default minimum journey under review is ending the current context; all-device logout is not assumed.

## Main behavior
Invalidate the current session's refresh token and immediately reject its already-issued access tokens, as specified by the user. Requests already admitted may finish under the general authentication policy; other sessions are unaffected. Organization guarded mutations have the narrower commit-order guarantee recorded by TASK-DP-003-018: revocation committed first prevents the mutation, while a mutation holding the session lock finishes before revocation can commit. This does not settle the future refresh/logout HTTP race contract. After confirmation, new protected requests relying solely on the ended context require authentication again. Repeated logout must not recreate authenticated access.

## Validation, business rules and authorization
A user must not end another person's context by supplying a different user/session identifier. Logout does not delete identity, membership, historical audit or approval decisions. NFR-002/NFR-004 apply.

## Failure and edge cases
Define concurrent protected requests and continuation attempts at the completion boundary. If logout cannot be confirmed, give a safe failure/retry outcome rather than claiming server-side access ended. Other sessions follow the reviewed policy, not an assumed global logout.

## Verification criteria
- After confirmed logout, replay of the ended context cannot start a new protected operation or continuation.
- Repeating logout is safe and grants no access.
- Manipulating a target identifier cannot log out another user.
- An unconfirmed failure is distinguishable from completed logout without exposing secrets.

## Open questions
D-006: concurrent refresh/logout ordering, confirmation and retry semantics. D-004: coordination with expiry and refresh-token rotation.
