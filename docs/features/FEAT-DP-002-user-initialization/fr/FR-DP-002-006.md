# FR-DP-002-006 — End the reviewed logout scope safely

## Requirement statement
The system shall end the authentication context selected by the reviewed logout policy and confirm logout only when that policy's completion condition is satisfied.

## Preconditions and trigger
An authenticated user requests logout, or repeats logout for a context already ended. The default minimum journey under review is ending the current context; all-device logout is not assumed.

## Main behavior
Invalidate the current session's refresh token and immediately reject its already-issued access tokens, as specified by the user. Requests already admitted may finish under the general authentication policy; other sessions are unaffected. Organization guarded mutations have the narrower commit-order guarantee recorded by TASK-DP-003-018: revocation committed first prevents the mutation, while a mutation holding the session lock finishes before revocation can commit. For a race with refresh, logout wins (D-006, 2026-11-09): both serialize on the session, and a refresh that commits first is followed by revocation of its newly rotated token and access tokens. After confirmation, new protected requests relying solely on the ended context require authentication again. Repeated logout must not recreate authenticated access.

## Validation, business rules and authorization
A user must not end another person's context by supplying a different user/session identifier. Logout does not delete identity, membership, historical audit or approval decisions. NFR-002/NFR-004 apply.

## Failure and edge cases
Logout is idempotent: a repeated logout, or one presenting an expired, revoked or missing refresh proof, returns the same success outcome (204 No Content) and clears the client's refresh proof without revealing session state. Only an unexpected server failure returns a 5xx outcome; the client may retry, and the server never reports success for a revocation that did not commit. Other sessions follow the reviewed policy, not an assumed global logout.

## Verification criteria
- After confirmed logout, replay of the ended context cannot start a new protected operation or continuation.
- Repeating logout is safe and grants no access.
- Manipulating a target identifier cannot log out another user.
- An unconfirmed failure is distinguishable from completed logout without exposing secrets.

## Open questions
None blocking. D-006 resolved 2026-11-09 (logout wins; idempotent 204). D-004 lifetimes and rotation remain as confirmed; their security review is still pending.
