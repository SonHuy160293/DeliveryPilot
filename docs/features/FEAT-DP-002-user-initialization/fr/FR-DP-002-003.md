# FR-DP-002-003 — Authenticate an eligible existing user

## Requirement statement
The system shall establish an authenticated context only when the supplied proof is valid for an existing identity that is eligible to sign in.

## Preconditions and trigger
A returning user submits email and password. An active account is eligible even when its email has not been verified, as confirmed by the user on 2026-11-02.

## Main behavior
Verify the proof and current account eligibility before confirming login. Bind the authenticated context to the verified user identity. Return authentication tokens as specified by FR-DP-002-005 without creating or inferring memberships; the client chooses the onboarding or workspace step when no membership exists.

## Validation, business rules and authorization
A claimed user ID, email, role or TenantId is not proof. Keep authentication distinct from resource authorization (BR-004, BR-005, BR-008; FR-DP-002-007). Apply session validity requirements in FR-DP-002-005.

## Failure and edge cases
Invalid proof, an unknown identity, unmet activation conditions or an ineligible account must not establish new authenticated access. For an unknown email, incorrect password or inactive account, return the same user-confirmed message, "Invalid email or password.", without revealing the reason. A dependency failure must not fall back to accepting the claimed identity.

## Verification criteria
- Valid proof for an eligible identity establishes access as that identity only.
- Invalid proof or ineligible account state establishes no authenticated context.
- A user without memberships can authenticate under the reviewed account policy without receiving tenant or approver access.
- A valid email/password for an active user can establish a context even when EmailVerifiedAt is null; pending, suspended and deleted users cannot authenticate while their account is not active.

## Open questions
The selected context lifetimes, refresh and logout behavior are described in FR-DP-002-005. On 2026-11-02, the user confirmed `401 Unauthorized` with code `Authentication.InvalidCredentials`, dummy PBKDF2 verification on unknown email/missing credential to equalize timing, updating `User.LastLoginAt` (UTC) in the login transaction while accepting `SuccessRehashNeeded` without mutating `PasswordCredentials`, and `200 OK` (`Cache-Control: no-store`) with `{ userId, accessToken, tokenType: "Bearer", expiresAt }` plus `Set-Cookie: dp_refresh_token` (`HttpOnly; Secure; SameSite=Strict; Path=/`, with `Expires` derived from `RefreshTokenExpiresAt`).
