# US-DP-003-003 — Switch authorized organizations

## Story

As a **person working across organizations**, I want to **discover and select my permitted workspaces**, so that I can work under the correct authority without duplicate accounts.

## Context and boundaries

Workspace means Organization/tenant boundary. Authentication and stored selection do not grant access. A person with no workspace membership may independently be a restricted project guest.

**State:** Jointly reviewed for requirements completeness, not client-approved or executed. Scenarios apply selected built-in defaults, protected-target rules and explicit delegated grants. Sources: [Workflow discovery](../../../deliverypilot-workflow-discovery.md) §2.2/§4; [Identity decisions](../../../architecture/modules/identity/design-decisions.md).

## Acceptance criteria

### AC-001 — Select A without mixing B

**Given** the person has eligible memberships in A and B.

**When** they discover their workspaces and select A for an A-scoped operation.

**Then** the selected operation uses A authority and discloses no B-only content.

### AC-002 — Revoked selection

**Given** the person previously selected A but their A membership has been removed.

**When** they later request membership-protected content in A.

**Then** the old selection and still-valid identity token grant no access to that content.

### AC-003 — No implicit project access

**Given** the person is a valid workspace member with no entitlement to a particular private project.

**When** they request that project.

**Then** workspace membership does not authorize its content or mutation.

### AC-004 — Zero memberships

**Given** an authenticated person has no eligible workspace memberships.

**When** they request their available membership-based workspace contexts.

**Then** the result supplies no membership-authorized workspace and does not create one automatically.

### AC-005 — Guest boundary

**Given** a person has an independently valid project-only guest grant and no workspace membership.

**When** membership-based workspace contexts are requested.

**Then** no general workspace membership is fabricated; the empty context list is not itself a denial of the separately owned guest grant.

### AC-006 — Unknown workspace

**Given** a person has no grant in B.

**When** they select or query B by an obtained identifier.

**Then** no restricted B membership or content is disclosed.

### AC-007 — Invalid remembered workspace

**Given** the remembered workspace is no longer eligible and another eligible workspace exists.

**When** navigation resumes.

**Then** a selector is shown without silently switching to the other workspace; permitted entries show name, stable identifier and the caller’s current roles.
