# US-DP-003-001 — Create organization

## Story

As a **registered person**, I want to **create a workspace and become its initial Owner**, so that I can establish an explicit ownership boundary for delivery work.

## Context and boundaries

Creation is separate from registration and does not require an existing workspace membership. Q1/CREATE-01/U9 select creator authority and the name-only input. Initial Owner establishment is not the additional-Owner nomination workflow.

**State:** Jointly reviewed for requirements completeness, not client-approved or executed. Scenarios apply selected built-in defaults, protected-target rules and explicit delegated grants. Sources: [Workflow discovery](../../../deliverypilot-workflow-discovery.md) §2.2/§4; [Identity decisions](../../../architecture/modules/identity/design-decisions.md).

## Acceptance criteria

### AC-001 — Create with initial Owner

**Given** a currently eligible authenticated registered person and the name "  North Team  ".

**When** the person creates a workspace.

**Then** the workspace is named "North Team", its creator has the membership and initial Owner assignment, and the creation is attributable.

### AC-002 — No implicit access

**Given** another authenticated person has no membership or other applicable workspace grant.

**When** they request the new workspace’s protected content.

**Then** no restricted workspace content is disclosed; knowing its identifier grants no authority.

### AC-003 — Duplicate name is allowed

**Given** a workspace named "North Team" exists and a person intentionally creates a separate workspace with that name.

**When** the independent valid request is processed.

**Then** the name alone does not reject creation; the workspaces have distinct identity and isolated authority.

### AC-004 — Name boundaries

**Given** separate requests contain empty, whitespace-only, 160-character nonblank, and 161-character names.

**When** the requests are validated.

**Then** the first, second and fourth create nothing; the 160-character name is eligible without a slug or additional business field.

### AC-005 — Atomic establishment

**Given** workspace creation cannot complete the initial Owner membership/assignment.

**When** the creation fails.

**Then** no usable workspace lacking its initial Owner is left behind and no success is reported.

### AC-006 — Unauthenticated caller

**Given** a caller has no valid authenticated identity.

**When** they request creation.

**Then** no workspace, membership or Owner grant is created.

### AC-007 — Same creation attempt replay

**Given** the same person completed creation and retains current access to its result.

**When** they retry the same attempt with the same name within 24 hours.

**Then** the original authorized outcome is returned without another workspace, membership or initial Owner grant.

### AC-008 — Conflicting creation attempt content

**Given** a creation attempt already identifies a completed workspace.

**When** the same person retries that attempt within 24 hours with a different name.

**Then** a conflict is returned without changing the original workspace or creating another.

### AC-009 — Expired creation attempt

**Given** the original attempt is outside its 24-hour replay period.

**When** the caller retries that attempt.

**Then** the request is rejected with explicit new-attempt guidance and does not silently create another workspace.
