# FR-DP-003-004 — Select authorized organization context

## Requirement statement

The system shall let an authenticated person discover their permitted workspace memberships and select a currently authorized workspace without exposing another workspace’s resources.

**Origin and state:** Jointly reviewed behavioral contract for task planning. [Workflow discovery](../../../deliverypilot-workflow-discovery.md) §2.2/Q1–Q3; [Identity decisions](../../../architecture/modules/identity/design-decisions.md) SCOPE-04, MEM-01 and ACCESS-01. User-selected rules retain their stated scope; BA-derived scenarios elaborate those choices without claiming customer approval or implementation.

## Preconditions and trigger

The person requests their available workspaces or selects a workspace for an organization-scoped operation.

## Main behavior

Limit membership-based discovery to the person’s currently eligible memberships. Validate actual scope and current authority for each protected operation; a stored selection is navigation context, not a grant. NAV-01/U18 selects workspace name, stable identifier and the caller’s current roles for the selector. Remember the last selection only while eligible; otherwise show a selector without silently changing tenant. A person with no eligible memberships receives create/join guidance and no membership-authorized workspace context. Do not manufacture membership for a project-only guest or treat this empty list as revocation of independently authorized project participation. Selecting A does not transfer roles/data from B.

## Validation, business rules and authorization

BR-002/003/005/008; NFR-001/002/004. Project/guest navigation and resource checks belong to FEAT-DP-004/015. This draft does not choose client storage, request headers or cache technology.

## Failure and edge cases

Unknown workspace, removed/suspended membership or unestablished current authority cannot authorize a workspace operation. Stale selection must not disclose restricted titles/links or content. The selected fallback is a selector/empty state, not automatic tenant switching. LIFE-01/U19 requires active workspace state for normal access. ACCESS-02 denies new decisions after revocation, permits admitted reads to finish, and fails closed on unavailable required facts. Lifecycle commands are deferred, not inferred from navigation.

## Verification criteria

- A user with eligible memberships in A and B can select A without receiving B-only information.
- Membership-authorized discovery exposes no unrelated workspace.
- A removed membership cannot authorize a later operation merely because it is selected.
- A zero-membership user has no membership-authorized workspace context; no automatic workspace/membership is created.

Criteria reflect the selected scope and are not executed test results. Explicitly deferred capabilities below are outside this release.
