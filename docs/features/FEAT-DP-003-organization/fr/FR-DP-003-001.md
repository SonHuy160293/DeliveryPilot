# FR-DP-003-001 — Create organization and owner membership

## Requirement statement

The system shall let an authenticated registered person create a workspace and become its initial Owner, with workspace creation separate from registration.

**Origin and state:** Jointly reviewed behavioral contract for task planning. [Workflow discovery](../../../deliverypilot-workflow-discovery.md) §2.2/Q1; [Identity decisions](../../../architecture/modules/identity/design-decisions.md) OWN-01 and CREATE-01/U9. User-selected rules retain their stated scope; BA-derived scenarios elaborate those choices without claiming customer approval or implementation.

## Preconditions and trigger

A registered person with current authenticated account eligibility explicitly requests workspace creation. No existing organization membership is required.

## Main behavior

Accept only a trimmed, nonblank display name of at most 160 characters. Duplicate display names are allowed; no slug or additional business field is required. Establish the workspace, creator membership and initial protected Owner assignment consistently; record attributable creation evidence. Failure must not leave a usable workspace without its initial Owner. Creation grants no Project participation or platform privilege.

## Validation, business rules and authorization

BR-002 permits multiple memberships; BR-003 separates project access; BR-008 prohibits trusting a supplied tenant ID. NFR-001/002 cover scoped access, NFR-003 creation attribution and NFR-004 consistent establishment. Initial Owner establishment is the creation rule, not ordinary delegation from a preexisting role.

## Failure and edge cases

Unauthenticated or ineligible callers and invalid names cause no creation. Blank/whitespace-only and over-limit names fail. Independent workspaces may share a name. CREATE-02/U14 selects retry protection: same person and same creation attempt within 24 hours returns the original outcome only while currently authorized to view it; changing the name on that attempt conflicts without creating another workspace. An explicitly new attempt may create a separate same-name workspace. REPLAY-01/U21 rejects an expired attempt with explicit new-attempt guidance; never silently turn it into another workspace.

## Verification criteria

- Successful creation establishes the trimmed name, creator membership and Owner assignment together.
- Empty, whitespace-only and 161-character names create nothing; 160-character nonblank names are accepted.
- An independently requested second workspace with the same name is not rejected solely for its name.
- Failure while establishing membership/ownership leaves no usable orphan workspace; another user receives no access through the creator action.

Criteria reflect the selected scope and are not executed test results. Explicitly deferred capabilities below are outside this release.
