# FR-DP-003-011 — List and inspect authorized memberships

## Requirement statement

The system shall expose workspace membership details only to callers currently authorized to inspect those details within that workspace.

**Origin and state:** Jointly reviewed behavioral contract for task planning. [Feature scope](../feature.md#in-scope-for-this-release) and [Workflow discovery](../../../deliverypilot-workflow-discovery.md) Q2/Q3; proposed read contract grounded in NFR-001/002/008. User-selected rules retain their stated scope; BA-derived scenarios elaborate those choices without claiming customer approval or implementation.

## Preconditions and trigger

A caller requests a workspace member list or an individual membership. The relevant read authority and permissible field set must be established.

## Main behavior

**Selected readership (AUTHZ-07/U11):** Owners/Admins and explicitly delegated member-list readers may inspect the workspace member list/current roles; each member may inspect their own membership/roles. **Selected fields (DATA-04/U12):** provide display name, primary email, membership state, current workspace roles and join time to authorized member-list readers, keeping pending invitations distinct from joined members. Reading a member does not grant role-management/removal powers or project access. DATA-05/U18 defines original membership creation time, preserved across rejoin; default active list with explicit removed/suspended filters. Historical roles require separate audit-read access; current inactive assignments supply no effective grant. ordinary members receive no general member-list grant merely from membership.

## Validation, business rules and authorization

BR-003/005/008; NFR-001/002/008. Feature initial membership-listing scope supplies the need; reader eligibility is selected in AUTHZ-07/U11; the member field set is selected in DATA-04/U12; historical visibility and original join time are selected in DATA-05/U18. Exclude credentials, sessions, invitation proofs and unrelated workspace data.

## Failure and edge cases

Unauthorized/foreign-workspace queries disclose no restricted membership existence or personal detail. Removed members cannot use a historical relationship to inspect the list. Search/count/page behavior must obey the same scope, without specifying an API or pagination format.

## Verification criteria

- A reader with explicitly established member-read authority sees only the selected permitted fields for the authorized workspace.
- An actor without that authority cannot enumerate membership existence or details.
- A permitted read does not confer assignment/removal or project authority.
- A pending invitation is not represented as an active membership.

Criteria reflect the selected scope and are not executed test results. Explicitly deferred capabilities below are outside this release.
