## Behavior and invariants

- Use authenticated server subject/session; load current active account, active workspace, membership and current role definitions/assignments. Never grant from request actor IDs, TenantIds/Permissions claims, cached UI context or a platform assignment.
- Implement the [selected capability matrix](../feature.md#3-selected-rules-and-decision-provenance). Codes in the [backend plan](../backend-plan.md#capability-catalog-mapping) map one-to-one to selected powers; protected ownership is nondelegable and recognized by system Owner assignment, not a custom role name.
- Grants require role-management authority and every granted code held/catalog-delegable. Admin-role reductions and Admin membership removal require Owner. Other removal actors need removal permission and target effective powers within theirs. Multi-role Owner target uses Owner protections.
- For every workspace security mutation acquire the organization row FOR UPDATE inside the existing transaction; all membership/role/offer/Owner writers use this guard. Read current actor/role state after the guard and retain it through pipeline commit. Lock active actor eligibility rows for the write decision as needed so a competing account-state write cannot invalidate the checked decision before commit; use documented consistent lock order.
- Count active Users + active memberships + effective Owner assignments, not logged-in sessions. Normal reductions preserve an eligible Owner. No eligible Owner blocks privileged changes; compromised/suspended caller denied, valid ordinary reads remain scoped. New post-revocation decisions deny, admitted reads may finish, jobs reauthorize and unavailable required facts fail closed.

## Test matrix

- A-only membership, forged claims, Admin title or platform assignment cannot authorize B or private Project content.
- Admin/delegate cannot demote Admin then remove them; custom roles cannot install protected Owner/platform power.
- Two competing last-Owner reductions cannot both commit. Mutation after committed revocation fails; already-admitted read/job boundaries follow U19.
- Authoritative store outage denies effects rather than accepting claims; fresh definitions override stale role/grant projections.
