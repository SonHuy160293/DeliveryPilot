# TASK-DP-003-016 — Honor persisted built-in role permission versions

## Objective and source contract

Prevent a new code catalog from silently changing existing workspace Owner/Admin effective permissions; US-DP-003-006 AC-012 and AUTHZ-12 require reviewed template upgrades. Requirements are internally ready, not client-approved.

## Codebase evidence

Reviewed and implemented 2026-11-04. [OrganizationCapabilityCatalog](../../../../src/Modules/DeliveryPilot.Identity/DeliveryPilot.Identity.Domain/Authorization/OrganizationCapabilityCatalog.cs) now derives Owner/Admin permissions from scoped persisted rows filtered against the catalog. [OrganizationAuthorizationService](../../../../src/Modules/DeliveryPilot.Identity/DeliveryPilot.Identity.Infrastructure/Security/OrganizationAuthorizationService.cs) and [OrganizationMutationGuard](../../../../src/Modules/DeliveryPilot.Identity/DeliveryPilot.Identity.Infrastructure/Security/OrganizationMutationGuard.cs) load persisted role permissions and share that evaluator. [Role permission mapping](../../../../src/Modules/DeliveryPilot.Identity/DeliveryPilot.Identity.Infrastructure/Persistence/Configurations/OrganizationRolePermissionConfiguration.cs) scopes role rows to the owning organization. [Security tests](../../../../tests/DeliveryPilot.Identity.Tests/Security/OrganizationAuthorizationAndGuardTests.cs) and [creation tests](../../../../tests/DeliveryPilot.Identity.Tests/Organizations/OrganizationCreationTests.cs) verify the changed behavior.

## Scope and dependencies

Dependencies 002 and 004 are done. Change existing authorization evaluation and tests only; no public route, schema migration, existing-data rewrite, template upgrade or external deployment. Missing data fails closed; detect/report discrepancy without repair.

## Behavior and invariants

- A non-retired Owner uses only persisted matching organization/role permission rows present in the known catalog; Admin uses only matching delegable rows; Member grants no general permission. Custom-role filtering remains delegable-only. Missing, unknown, nondelegable or cross-scope rows do not create authority.
- Preserve active account/membership/workspace eligibility, protected system role identification, Owner-only Admin reductions, last-owner continuity, actor/target ceilings and project boundaries.
- Creation continues to seed the current selected template into role-permission rows. TemplateVersion is evidence of the seed, not an implicit authority source; deployments do not change existing grants.

## Persistence and integrations

Read existing Identity rows; no changes to schema or persisted data. Preserve Identity transaction and guard boundaries. Do not backfill missing or unexpected rows. Review an isolated test database's definitions and report whether any discrepancies were observed, without extrapolating to deployed data.
