## Behavior and invariants

- Authenticate the server subject, acquire the shared organization mutation guard inside the command transaction, and recheck actor eligibility and role-management authority from current state. A foreign scope or unestablished authority returns generic denial before revealing target facts.
- Load the scoped role and require a mutable custom role and the current expected version. Reject system roles, stale or already-retired intent as conflicts. Require a trimmed nonblank reason of at most 1,000 characters.
- While retaining the guard through commit, reject retirement when any current assignment exists or any persisted pending invitation offer references the scoped role. A stored pending invitation remains blocking until its lifecycle transition closes it; do not infer closure from a deadline without applying the lifecycle rules. Preserve all assignments, offers, audit facts and role identity.
- Atomically retire the role and stage the required allowlisted retirement audit event; audit or commit failure rolls back the transition. Successful retirement prevents subsequent assignment and offer creation. Assignment and issue/reissue writers must acquire the same guard and re-read role state after acquiring it.

## API contract (only for API tasks)

**Implemented bearer route:** POST /api/v1/organizations/{organizationId}/roles/{roleId}/retire with closed body `{expectedVersion,reason}`. The server derives actor and time. `expectedVersion` is a positive long; the reason is required and trimmed as above. Return 200 with the existing planned RoleSummary: `id,code,name,description,origin,permissionCodes,version,permissionSetVersion,retiredAt`, in the existing ApiResponse envelope and with no-store. Handlers prepare response data; controllers select HTTP results.

Malformed body, unknown fields, invalid version/reason -> 400; unauthenticated -> 401; missing authority or foreign scope -> generic 403; missing role -> 404 only after current scoped role-management authorization; stale intent, built-in/already-retired role, current assignment or pending offer -> 409 without exposing private offer details; unavailable required facts -> 503. Required audit/write failure cannot return success. Errors retain safe codes and trace IDs under current middleware conventions.
