## Behavior and invariants

- Available workspaces are only current active workspace/active membership relationships of the caller, with organizationId, name, own roles and keys/versions; duplicates distinguished by ID. Empty membership list stays empty and creates nothing.
- Any eligible member may inspect own membership/roles. General list/read requires member-read capability; default active records, explicit active/removed/suspended filters for permitted readers. JoinedAt is original CreatedAt; current inactive assignments confer no effective roles.
- Allowed visible member fields: displayName, primaryEmail, membership status, current workspace roles, joinedAt; membershipId/userId and revision are scoped technical identifiers for permitted actions. Do not emit historical roles unless audit-read API separately authorizes them.
- All pages recheck current authority. Current selection/claims cannot authorize a removed workspace. Expose no private project facts; zero memberships does not invalidate independent guest entitlements.

## API contract (only for API tasks)

**Bearer routes:** GET /api/v1/me/organizations -> {items:[{organizationId,name,roles,membershipId,version,membershipVersion}],nextCursor}; GET /api/v1/organizations/{organizationId}/members/me -> own MemberSummary; GET /api/v1/organizations/{organizationId}/members and GET .../members/{membershipId} -> authorized MemberSummary/list.

MemberSummary fields are membershipId,userId,displayName,primaryEmail,status,roles:[{id,code,name}],joinedAt,version; non-active effective roles are empty. Both lists use limit default 50/max 100 and a bounded opaque base64url keyset cursor (maximum 1,024 characters); malformed values return 400. Workspace pages sort ascending by organization CreatedAt and organization Id; member pages sort ascending by membership CreatedAt and membership Id. Use the corresponding UTC timestamp and stable ID for the cursor and strictly greater keyset predicate; `nextCursor` is null when no further row exists. Member status defaults active and accepts explicit active/removed/suspended. Document ordering and the lack of a snapshot guarantee in README. All success responses 200 ApiResponse with no-store. 401 no identity, generic 403 for unavailable scope/no grant, 404 only a missing target inside an already-authorized workspace, 503 unavailable scoped facts. Unknown/cross-scope IDs never disclose existence.
