## Behavior and invariants

- Only current active Owner nominates an active same-workspace non-Owner member; no new nomination for already-Owner target and at most one pending per workspace/member. Duplicate pending conflicts; expired pending closes before fresh nomination.
- Nomination alone grants nothing. Seven-day deadline; acceptance requires same nominated subject, active membership/account and current active Owner sponsor. Any current Owner may cancel; nominee may decline. No membership-invitation proof or automatic resend lifetime restart.
- First valid committed terminal transition wins; accepted replay is only current authorized already-accepted outcome with no new grant. Close nomination and add protected Owner assignment/new grant period plus audit together.
- Existing Owners remain after acceptance. Transfer is a later explicit 011 step-down with required reason and continuity; Member fallback/retained roles are not part of the acceptance transaction.

## API contract (only for API tasks)

**Implemented bearer routes:** POST /api/v1/organizations/{organizationId}/ownership-nominations {membershipId} -> 201 NominationSummary; GET same collection for Owners; GET /api/v1/me/ownership-nominations for only the caller’s eligible nominations. POST .../ownership-nominations/{nominationId}/accept or /decline {expectedVersion}; /cancel {expectedVersion,reason?} -> 200 terminal/current NominationSummary.

Summary contains exactly id,organizationId,membershipId,nominatedByUserId,status,createdAt,expiresAt,version,canAccept, with no email/proof or additional display-name fields. Only the nominated subject can accept/decline without gaining general member-list rights. Lists default to status=pending and limit=50, maximum 100, accept all lifecycle status filters, use bounded created-time/ID keysets and return items/nextCursor. Private results and errors use no-store, mutations enforce 16,384-byte body limits, unknown fields are rejected and versions must be positive. Cancellation reason is optional and follows the existing bounded safe audit-reason policy.

400 invalid/unknown body; 401 unauthenticated; generic 403 Organization.AccessDenied for wrong actor/workspace or unavailable scope; 409 OwnershipNomination.Stale, PendingExists, AlreadyOwner, SponsorUnavailable, RecipientUnavailable or Closed as appropriate after authorization; safe 413 Request.TooLarge for oversized bodies; 503 Organization.AuthorityUnavailable for required fact outages; safe 500 for unexpected persistence failures. Matching same-closing-subject replay returns the current summary without mutation and ignores stale positive versions. Accepted replay additionally requires the original accepting subject still hold current active Owner authority; it never restores removed/demoted access or reruns sponsor/deadline checks for a new grant. Decline remains available to an eligible nominee after sponsor loss. Server obtains sponsor/time; no caller-selected Owner role or deadline.
