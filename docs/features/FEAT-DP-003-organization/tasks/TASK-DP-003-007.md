## Behavior and invariants

- One pending invitation per OrganizationId/normalized email; immutable offered RoleId, PermissionSetVersion and code snapshot per offer. Snapshot version is not a mutable Role FK. Fresh authorized reissue closes prior offer and creates a linked new offer; resend keeps role intent, rotates proof and resets seven days.
- Capture the offered role's trimmed display name (1–160 characters) with each immutable role offer. Rename does not change an existing offer or require reissue. Resend preserves the snapshot; reissue captures the then-current name in the new offer. Retain the snapshot for workspace lifetime with the offer and never treat its name as authority.
- Invitation issue/reissue writers must acquire the shared organization mutation guard and check current role state under that guard; they must never create an offer for a retired role. TASK-DP-003-015 later adds retirement under the same guard and tests the race against this path. No retirement endpoint is introduced here.
- Use a random 32-byte secret encoded base64url; store only a 32-byte purpose/organization/invitation-bound verifier in the invitation. Never log/return secret except to the encrypted delivery stager at issue; comparisons constant-time. Current primary-email match and bearer identity remain independent requirements.
- Persist actual deadline and deny at/after expiry even before cleanup. Active membership uses role management, removed gets fresh-authorized rejoin, suspended cannot join. Preview/decline proof requires the same current matching account; first valid terminal transition wins.
- Issue/Resend/Reissue share configurable rolling limits: pair 60-second cooldown and 10 issuances/24h, workspace 100/hour. Count committed proof generations, including later cancelled offers, not delivery retries; check under common organization guard so races cannot exceed limits. A blocked attempt stages no proof/offer/deadline extension.
- Accepted replay is a currently authorized no-change result; it never restores access or grants. Same User/workspace membership identity and fresh grant periods survive rejoin.

Technical addition: nullable CurrentDeliveryMessageId on Invitation, a scalar marker validated by the aggregate, not a circular FK. New shared.OrganizationInvitationDeliveries ledger: DeliveryMessageId uuidv7 PK; OrganizationId/InvitationId scoped restricted FK; immutable IssuedAt/ExpiresAt; Status, LastEventSequence bigint default0, FailureCode nullable, UpdatedAt, Version. No plaintext proof/email copy in ledger. Index OrganizationId/IssuedAt and InvitationId/IssuedAt; join immutable recipient to count pair issuances. This ledger provides proof-generation identity and monotonic delivery projection without mutating invitation intent/version for every receipt.
