## Behavior and invariants

- Owner/Admin defaults or explicit action grant, plus current allowed role delegation, govern each operation. Validate roles within the same organization; no Owner/platform role offer. Active member cannot be invited, removed may rejoin fresh, suspended is blocked.
- Issue/reissue must retain the shared organization mutation guard through commit and re-read role state under it; retired roles cannot be newly offered. TASK-DP-003-015 tests these actual writers against retirement after this task is complete.
- Duplicate pending Issue conflicts; an authorized operator explicitly chooses Resend/Reissue. Expired pending rows close before fresh issue. Resend retains original sponsor/offer and requires that sponsor still be valid; it rotates proof/deadline. Repairing lost sponsor authority requires a fresh authorized Reissue.
- Reissue pins newly authorized role snapshots in a new linked offer and closes old proof; cancellation requires reason and current authority. Closed offer cannot be resent; cancelling accepted offer cannot revoke membership.
- Manager projections use 007's immutable offered role name: issue captures the current name, resend retains it after rename, and reissue captures the then-current name for the new offer.
- Each proof generation commits invitation/current marker/ledger/required history/encrypted outbox atomically. No token in response; reuse provider/delivery status without claiming receipt equals delivered. Enforce shared issuance limits and expose safe Retry-After.
- Member/invitation existence detail is conditional on separate read authority. A delegated issue-only caller receives generic eligibility/conflict feedback without hidden membership names, state, prior offer IDs or role data.

## API contract (only for API tasks)

**Implemented bearer routes:** POST /api/v1/organizations/{organizationId}/invitations with {recipientEmail,roleIds:[uuid]} -> 201 InvitationSummary. Recipient normalizes via User.NormalizeEmail, valid email 3–320; roleIds distinct nonempty GUIDs, bounded by 16KB request. GET same collection with status/limit/cursor -> 200 paged permitted offers. GET .../invitations/{invitationId} -> 200 permitted summary. List defaults to persisted status pending and limit 50 (maximum 100), ordered by UTC creation time and ID; cursors use the shared bounded keyset format.

POST .../{invitationId}/resend {expectedVersion,reason?}; /reissue {expectedVersion,roleIds,reason}; /cancel {expectedVersion,reason} -> 200 current/new InvitationSummary. Summary: id,organizationId,recipientEmail,status,offeredRoles:[{roleId,name,permissionSetVersion}],expiresAt,version,delivery:{status,failureCode?,updatedAt}; no proof/verifier. Names/snapshots reflect the offer, not silently changed permissions. Cancellation/reissue reason nonblank <=1,000.

400 validation/unknown fields; 401 no identity; generic 403 missing action/scope; 404 target only after permitted scope/read; 409 Invitation.PendingOfferExists, RecipientUnavailable, OfferChanged, Closed or stale intent without sensitive details; 413 Request.TooLarge for the enforced body ceiling; 429 Invitation.RateLimited with Retry-After and no mutation; safe 500/503 persistence/delivery-configuration failure. A caller without invitation-read authority gets the same generic RecipientUnavailable feedback for duplicate offers and ineligible recipients. Permission-specific list access is not implied by issue alone. Shared backend-plan conventions apply.
