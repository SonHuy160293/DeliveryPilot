## Behavior and invariants

- Name trimmed 1–160, case-insensitively workspace-unique; reserve Owner/Admin/Member names/codes. Description optional <=1,000. Generate immutable custom code from new stable role ID (role- followed by its N-format UUID); no caller-chosen system origin/template/version.
- Expose registered organization-delegable catalog codes only. Role manager must hold every newly granted code and management authority. PermissionSetVersion advances on additions/removals even if codes later revert; metadata-only edit changes Version only.
- Multiple roles union allowed powers; mandatory restrictions survive. Owner cannot be assigned through this path. Admin-role demotion/revocation is Owner-only; ordinary role-management authority is insufficient.
- Reject grants and edits involving retired roles; require an Admin-reduction reason. No automatic built-in definition updates. Retirement and its mandatory reason/current assignment/pending offer checks are owned by TASK-DP-003-015.
- Reauthorize then return no-change for identical already-applied grant/revoke without new GrantVersion; stale differing edit returns conflict for refresh, no silent merge. Genuine regrant uses stable assignment and new grant period.

## API contract (only for API tasks)

**Bearer routes:** GET /api/v1/organizations/{organizationId}/permissions -> {codes}; GET .../roles -> {items:[RoleSummary],nextCursor}; POST .../roles -> 201 RoleSummary; PUT .../roles/{roleId} -> 200 RoleSummary. RoleSummary: id,code,name,description,origin,permissionCodes,version,permissionSetVersion,retiredAt. CreateRoleRequest {name,description?,permissionCodes:[string]}; Update adds expectedVersion. TASK-DP-003-015 owns the separate retirement endpoint.

POST .../members/{membershipId}/roles/{roleId}/grant and /revoke take {expectedMembershipVersion,reason?} -> {membershipId,version,roles,changed}; Admin revoke requires reason. Empty/duplicate/unknown codes, bad versions and unknown fields 400; no permission/cross-scope 403; scoped missing role 404; stale, reserved/duplicate name or built-in edit conflict 409; success no-op 200 changed:false. Role/catalog browsing requires role-management or ordinary-assignment/invitation authority within allowed delegation; not a public member directory.
