# TASK-DP-003-019 — Expose internal session and workspace authority checks for other hosts

## Objective and source contract

Give independently hosted modules (first: the planned `DeliveryPilot.Projects` module) a reviewed, internal-only way to ask Identity two questions, without reading Identity's database:

1. **Session check:** is `(userId, sessionId)` still an active session of an active account?
2. **Workspace authority check:** for `(userId, sessionId?, organizationId)`, is the caller an eligible active member of an active organization, and what are their current effective workspace roles and permission codes?

Sources (all `ready`, `approval_ref: null`; readiness is internal completeness, not client approval):

- [FR-DP-003-005](../fr/FR-DP-003-005.md): revocation applies to decisions begun after commit, queued work reauthorizes at execution, unavailable required facts fail closed (ACCESS-02/U19).
- [FR-DP-003-007](../fr/FR-DP-003-007.md): organization facts are evaluated only for organization scope and never imply project access.
- NFR-001/002 tenant isolation and least privilege; NFR-009 correlation/observability; NFR-011 module contracts without cross-module coupling.
- Architecture: [ADR-001](../../../architecture/adr-001-delivery-module-placement.md) D-02 (shared-key bearer validation **plus** Identity session check), D-03 (internal non-Gateway authority query), D-04 (commands uncached; fail closed). Identity [minimum external contracts](../../../architecture/modules/identity/design-decisions.md#minimum-external-contracts) "Account/session eligibility" and "Organization eligibility".

This is a technical/NFR task; no User Story is invented.

## Behavior and invariants

- Both checks read authoritative Identity state **uncached** per call and never trust caller-supplied tenant, role or permission claims.
- Session check returns `active: true` only when the session exists, belongs to the user, is not revoked and the user is active. Same predicate as `AuthenticatedContextValidator`; reuse it rather than duplicating the query.
- Workspace authority check:
  - with `sessionId`: interactive request, so the session must be active (as above);
  - without `sessionId`: queued-work reauthorization (ACCESS-02), with the same membership/organization checks and no session check (mirrors `ReauthorizeJobActorAsync`);
  - optional `requiredPermissionCode`: denied unless the member currently holds it.
- **Denial is an answer, not an error:** an ineligible caller yields HTTP 200 with `decision: "denied"` and **no** reason, membership, role or existence details, so the caller cannot enumerate organizations or memberships. Implement via a non-throwing evaluation method (e.g. `EvaluateActorAsync` returning `null` on denial) instead of catching `ForbiddenException` for control flow. Store failures still throw `ServiceUnavailableException` → 503.
- The response never includes email, display name, credentials, session material or other members' data.
- Results grant no project access (FR-DP-003-007). The DTO documents that callers decide resource authority themselves.
- Queries do not open command transactions. No audit event is written for checks (reads), but structured logs/traces carry the correlation ID without the API key.

## API contract (proposed; not yet implemented)

Base: Identity API `api/v1/integrations/authority/…` via a new `AuthorityController : IntegrationApiController`. **Never published through the Gateway.**

- **Authentication:** `X-Integration-Key` (existing filter). Add a dedicated key for the Projects caller to `IntegrationApi:ApiKeys`; keys are secrets, never logged.
- **`POST integrations/authority/session-checks`**
  - Body `SessionCheckRequest { userId: Guid (required, non-empty), sessionId: Guid (required, non-empty) }`.
  - 200 `SessionCheckResult { active: bool }`.
- **`POST integrations/authority/organization-checks`**
  - Body `OrganizationAuthorityCheckRequest { userId: Guid (required), organizationId: Guid (required), sessionId: Guid? (optional; non-empty when present), requiredPermissionCode: string? (optional, ≤128 chars, registered catalog code format) }`.
  - 200 allowed:
    ```json
    { "decision": "allowed", "organizationId": "…", "organizationVersion": 7, "membershipId": "…",
      "membershipVersion": 3, "isOwner": false, "isAdmin": true,
      "effectivePermissions": ["organization.members.read"], "evaluatedAt": "2026-11-09T10:00:00+00:00" }
    ```
  - 200 denied: `{ "decision": "denied", "evaluatedAt": "…" }`.
- POST with a JSON body keeps identifiers out of URLs and access logs.
- **Errors:** 400 validation (`CqrsValidationException`: empty GUIDs, malformed code), 401 missing/invalid key (filter), 503 integration API unconfigured (filter) or `Organization.AuthorityUnavailable`; all via `GlobalExceptionHandlingMiddleware` with trace ID. No 403/404 on these routes.
- Both endpoints are idempotent reads; retries are safe.

## Test matrix

- **Positive:** active session → `active: true`; active member with session → allowed with correct versions, Owner/Admin flags and permission set; `requiredPermissionCode` held → allowed; no `sessionId` with active membership → allowed.
- **Negative/denied (same denied body):** revoked session, other user's session, suspended/inactive user, removed/suspended membership, inactive/unknown organization, member of A asking for B, permission not held. Assert the response body contains no membership/role data.
- **Validation:** empty GUIDs, empty-GUID `sessionId`, oversize/malformed permission code → 400 with trace ID.
- **Auth:** missing/invalid/duplicated key → 401; unconfigured keys → 503; bearer token alone → rejected.
- **Revocation timing (ACCESS-02):** after a committed membership removal or role revoke, the next check is denied / lacks the permission; after session revoke, the next session check is `false`.
- **Failure:** simulated store failure → 503 `Organization.AuthorityUnavailable`, never allowed.
- **Isolation/contract:** PostgreSQL-backed cross-tenant cases where `DELIVERYPILOT_TEST_POSTGRES` is available (report as not run otherwise); Gateway tests assert `/identity/api/v1/integrations/authority/...` paths are not routable.
- **No implicit project access:** response semantics and `CanAccessProjectResource` unchanged.
