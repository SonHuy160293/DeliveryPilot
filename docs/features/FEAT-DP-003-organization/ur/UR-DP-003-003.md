# UR-DP-003-003 — Participate in multiple organizations

## Problem and context

A global user may own one workspace and participate in others. A navigation choice must not move authority or private information between those contexts.

## User need

As an **organization member**, I need to **discover and select my permitted workspaces using one account**, so that I can work across organizations without mixing their data.

## Business value and observable outcome

Only eligible membership-based workspaces are offered; every protected operation retains its actual scope. A stale selection cannot restore lost access.

## Scope, constraints and exceptions

Zero workspace memberships is a valid account state. Project-only guests use separately authorized resource access; they must not be forced into general membership. BR-002/003/008; NFR-001/002/004. U18 selects remembering the last eligible selection and a selector/empty state otherwise; client storage/caching technology is task design.

## Evidence and validation

[Workflow discovery](../../../deliverypilot-workflow-discovery.md) §2.2/§4/Q1–Q6 and [Identity decisions](../../../architecture/modules/identity/design-decisions.md) SCOPE-04 and MEM-01. A user’s title, old selected workspace or global authentication is not a current workspace grant. These needs were jointly refined against the recorded user choices.
