# UR-DP-003-005 — Audit membership and role changes

## Problem and context

Operators need to explain who changed participation and permissions. Evidence stored internally does not alone satisfy the need to review it safely.

## User need

As an **authorized workspace audit reader**, I need to **review who created, changed or revoked membership and role access**, so that I can investigate changes without exposing unrelated information.

## Business value and observable outcome

Permitted readers can distinguish actor, time, action, outcome and historical transitions; removal/rejoin retains attribution while past grants remain distinct from current powers.

## Scope, constraints and exceptions

Recording and retrieval are separate capabilities. AUTHZ-07/U11 selects Owners/Admins and explicitly delegated audit readers; U20 selects the audit field set and reason rules; exact permission-code representation is task design; no implicit platform support bypass or export is included. NFR-001/002/003/004/008; BR-008. U20 selects workspace-lifetime history, required audit/write consistency and separate minimal denial telemetry; automated purge/erasure and durable denied-attempt history are deferred.
