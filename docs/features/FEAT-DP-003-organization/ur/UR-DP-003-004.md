# UR-DP-003-004 — Revoke access for departing members

## Problem and context

Departing members must lose membership-dependent authority without destroying earlier attribution or accidentally removing the last active Owner.

## User need

As an **authorized workspace membership operator**, I need to **end a departing person’s membership authority while keeping history**, so that I can protect the workspace and explain prior actions.

## Business value and observable outcome

Membership removal preserves the durable relationship and earlier actor history. Rejoin requires newly authorized roles; previous Admin grants do not return automatically.

## Scope, constraints and exceptions

Normal changes preserve an active eligible Owner. Other workspace memberships and global identity remain separate. U19 defines admitted-read, commit-recheck and queued-work boundaries. Project-owned participation remains independently authorized under its owning feature; no automatic grant cascade is introduced. BR-002/003/006/008; NFR-001/002/003/004/008. BR-007 remains a proposed project-removal rule rather than an organization cascade policy.
