## Behavior and invariants
- Schema `engagement`; plural PascalCase tables, PascalCase columns, quoted identifiers; UUIDv7 `Id` generated by the application; instants as UTC `DateTimeOffset`, calendar dates as `date`.
- Every table carries `OrganizationId` except `EngagementLinkAttempts` (see the ERD). `Engagements` exposes the alternate key `(OrganizationId, Id)`; children use the composite foreign key `(OrganizationId, EngagementId)`.
- `Version` is the optimistic concurrency token on `Engagements`, `EngagementMilestones`, `EngagementContacts` and `EngagementLinkCodes`, starting at 1.
- Constraints named in the ERD are created in the database:
  - checks: amount without currency; `Status` codes; `ClosedAt`/`ClosedByUserId` set iff Closed; the three client-link columns all null or all set; `ClientOrganizationId <> OrganizationId`; link-code `ExpiresAt = IssuedAt + 7 days`; consumed and invalidated column pairs;
  - partial unique indexes: one designated client PO per engagement among non-removed contacts; one `Outstanding` link code per engagement;
  - unique index on `EngagementLinkCodes.CodeVerifier` (32 bytes).
- `OriginalTargetDate` is not updatable after insert.
- `EngagementEvents` is append-only: the application never updates or deletes rows. Database grants for the API role are part of TASK-DP-025-012.
- Physical types, lengths and index names are decided here (PRJ-16) and become the source of truth with the migration.

## Persistence, events and integrations
- One new migration after `InitialReliability`, generated with `dotnet ef migrations add` in `DeliveryPilot.Projects.Infrastructure`. Do not edit the existing migration.
- Indexes implied by the ERD: `(OrganizationId, Status, CreatedAt, Id)`; non-unique `(OrganizationId, lower(AgreementReference))` filtered to Active; `(ClientOrganizationId)` filtered not null; `(OrganizationId, EngagementId, OccurredAt, Id)` on events; `(UserId, AttemptedAt)` on attempts.
- No cross-module foreign keys: `OrganizationId`, `ClientOrganizationId` and every `...UserId` are scalar Identity IDs.
- No outbox messages or integration contracts.

## Test matrix
- **Model (no database):** schemas are `engagement` and `reliability`; every `engagement` table except `EngagementLinkAttempts` has `OrganizationId`; the new migration is listed.
- **PostgreSQL:** migrations apply to an empty database and leave none pending.
- **Tenant isolation:** inserting a milestone, contact, link code or event whose `OrganizationId` differs from its engagement's fails on the composite foreign key.
- **Constraints:** each check and partial unique index above rejects the violating row (second designated client PO, second outstanding code, amount without currency, own-workspace link, wrong expiry).
- **Concurrency:** two contexts updating the same engagement from one version; the second save throws `DbUpdateConcurrencyException`.
- **Domain:** factories reject a 201-character client display name, a blank agreement reference, an `http` document link, three decimals in the amount and two decimals in person-days.
