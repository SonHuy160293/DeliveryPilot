## Behavior and invariants
- Authority: `IWorkspaceAuthority.RequireAsync` with `organization.engagements.create`, uncached, before anything is written.
- Required: client display name (trimmed, 1–200), agreement reference (trimmed, 1–100), agreement signed date. Optional: client legal name (≤200), country (ISO 3166-1 alpha-2, stored upper case), engagement name (≤200), document link (absolute HTTPS, ≤2000).
- The engagement is created Active, owned by the route workspace, with `CreatedByUserId` and UTC `CreatedAt`, `Version = 1`, no contract value, effort, milestones, contacts or link.
- Duplicate warning: when another Active engagement of the same workspace has the same agreement reference (trimmed, case-insensitive), creation still succeeds and the response carries `duplicateAgreementReference: true`.
- One `engagement.created` event is appended in the same transaction.
- Idempotency (PRJ-13): operation `engagement.create`, owner scope = workspace and user, fingerprint = normalized request. Same key and same request returns the existing engagement; same key with a different request gives 409 `Idempotency.KeyReused`; a concurrent duplicate creates one engagement.
- Accepted execution details (2026-11-11): PostgreSQL transaction advisory locks serialize the receipt key and the workspace/reference duplicate check. Authority is rechecked after blocking waits. Creation and replay return the original creation snapshot, retained in the append-only creation event JSON with the original duplicate warning; receipt/resource/event commit atomically. Completed receipts have no new expiry or cleanup policy. No handlers or stores save independently.
- Creation creates no users, memberships, Identity organizations or project access.

## API contract (only for API tasks)
- **Route base (mirrors Identity):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/engagements`. Not exposed through the Gateway until TASK-DP-025-013.
- **Authentication and tenant:** `[Authorize]`. User ID and session ID come from `ICurrentUserProvider` (`CurrentUser.Id`, `CurrentUser.SessionId`). The workspace is the route `organizationId`, confirmed by `IWorkspaceAuthority`; it is never taken from token claims or the body (BR-008).
- **Errors (through `GlobalExceptionHandlingMiddleware`):** 400 `CqrsValidationException`; 401 no valid session; 403 `ForbiddenException` when Identity denies the workspace or the required code is missing; 409 `ConflictException`; 503 `ServiceUnavailableException` when Identity cannot answer (fail closed). Creation has no existing engagement lookup or 404 visibility decision.
- **Method and route:** `POST .../engagements`.
- **Headers:** `Idempotency-Key`: required GUID, not empty (following Identity). Missing or malformed gives 400.
- **Body:** `clientDisplayName` (required), `agreementReference` (required), `agreementSignedOn` (required, ISO date), `clientLegalName`, `clientCountryCode`, `engagementName`, `documentUrl` (optional). Unknown members are rejected.
- **Success:** 201 for a new engagement, 200 for a replay. Body: `id`, `status`, `version`, the stored fields, `createdAt`, `duplicateAgreementReference`.
- **Errors:** 400 for blank or over-length fields, an invalid country code or a non-HTTPS link; 403 without the create code; 409 for key reuse; 503 when Identity is unavailable. Nothing is stored in any error case.
- Requests over the 16 KB ceiling return 413 `Request.PayloadTooLarge` through a Projects-local transport adapter. The shared exception middleware otherwise converts Kestrel's size exception to 500; preserve the shared behavior for other modules.
