# TASK-DP-025-008 — Close and reopen an engagement

## Objective and source contract
Let a manage holder move an engagement between Active and Closed with a reason, making a Closed engagement read-only. Sources: [FR-DP-025-007](../fr/FR-DP-025-007.md), [FR-DP-025-010](../fr/FR-DP-025-010.md); [US-DP-025-007](../us/US-DP-025-007.md) AC-001 and AC-003, and the edit half of AC-002; OQ-025-09, OQ-025-13. ## Scope and dependencies

**Out of scope:** rejecting new projects under a Closed engagement, which FEAT-DP-004's create-project task implements against the row lock described in the [ERD invariants](../../../architecture/modules/projects/erd.md#invariants-and-how-they-are-enforced); project closure (FEAT-DP-030); deletion.

**Depends on:** [TASK-DP-025-002](TASK-DP-025-002.md). It can run before or after tasks 004–007 and 009; whichever lands later must keep the Closed guard on its routes.

## Behavior and invariants
- Authority: `organization.engagements.manage`, uncached, before loading; then the engagement row is locked `FOR UPDATE`.
- Close: requires a non-blank reason; sets `Status = Closed`, `ClosedAt` (UTC) and `ClosedByUserId`; sets an `Outstanding` link code to `Invalidated` with `InvalidatedAt`; appends `engagement.closed`.
- Reopen: requires a non-blank reason; sets `Status = Active` and clears the closed columns; appends `engagement.reopened`. An invalidated link code stays invalidated.
- Closing a Closed engagement or reopening an Active one changes nothing and returns the current state (FR-DP-025-007: no change), with no event.
- Closing is allowed while projects under the engagement are active and does not touch them.
- A confirmed client link is kept at closing and can still be removed afterwards (OQ-025-13, implemented by TASK-DP-025-010).
- `expectedVersion` is compared as in TASK-DP-025-004.

## API contract (only for API tasks)
- **Route base (proposed, mirrors Identity):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/engagements`. Not exposed through the Gateway until TASK-DP-025-013.
- **Authentication and tenant:** `[Authorize]`. User ID and session ID come from `ICurrentUserProvider` (`CurrentUser.Id`, `CurrentUser.SessionId`). The workspace is the route `organizationId`, confirmed by `IWorkspaceAuthority`; it is never taken from token claims or the body (BR-008).
- **Errors (through `GlobalExceptionHandlingMiddleware`):** 400 `CqrsValidationException`; 401 no valid session; 403 `ForbiddenException` when Identity denies the workspace or the required code is missing; 404 `NotFoundException` for an engagement of another workspace or outside the caller's visibility, with the same response in both cases; 409 `ConflictException`; 503 `ServiceUnavailableException` when Identity cannot answer (fail closed).
- **Routes (proposed):** `POST .../engagements/{engagementId:guid}/close` and `POST .../engagements/{engagementId:guid}/reopen`.
- **Body:** `expectedVersion` (required), `reason` (required).
- **Success:** 200 with `status`, `version`, and the closed time and user when Closed.
- **Errors:** 400 for a missing reason; 403 without the manage code; 404; 409 for a stale version.

## Persistence, events and integrations
`Details` of `engagement.closed`: `{ invalidatedLinkCodeId }` when a code was invalidated (the ID only, never the code or verifier). Reason in `Reason`. No outbox message.

## Test matrix
- **Close:** status, closed columns, version and one event with actor, reason and UTC time; history and detail stay readable.
- **Outstanding code:** a seeded outstanding code becomes `Invalidated`.
- **Blocked edits:** after closing, the update, contract-value, milestone, contact and link-code routes that exist in the checkout return 409 and write nothing.
- **Reopen:** editing works again; the event records who reopened and why.
- **Idempotent state:** close on Closed and reopen on Active return 200 with no new event.
- **Race:** a close and a milestone edit running concurrently never leave an edit committed after the close.
- **Authorization and tenant:** no manage code gives 403; other workspace gives 404; Identity unavailable gives 503.
