# TASK-DP-025-009 — Issue a client organization link code

## Objective and source contract
Let a manage holder generate a single-use link code for an Active engagement that has no confirmed client link, shown once and stored only as a verifier. Sources: [FR-DP-025-008](../fr/FR-DP-025-008.md), [FR-DP-025-010](../fr/FR-DP-025-010.md); [US-DP-025-008](../us/US-DP-025-008.md) AC-001; OQ-025-10; PRJ-10; ADR-001 D-09. All source UR/FR/US are `ready` with `approval_ref: null`: complete for planning, not client-approved.

## Codebase evidence
Reviewed against commit `f84a9d5`: engagement creation, full-detail reads and the close/reopen mutation are implemented. `EngagementMutationService` authorizes manage permission, locks the tenant-scoped engagement row and rechecks authority; `ProjectsUnitOfWork` commits the transaction. `EngagementLinkCode` stores a defensive copy of a 32-byte verifier, has a seven-day expiry and a unique partial outstanding-code index. The detail read projects only expiry and does not load verifiers. Existing PostgreSQL-backed HTTP tests and the mutation store are reusable. No migration is needed. The user requested both link and project prerequisite chains to complete FR-DP-025-007; this task delivers issuance first. Generate 32 ungrouped uppercase Crockford-base32 characters (160 bits); hash the exact displayed code with SHA-256 so confirmation has a single canonical representation.
## Scope and dependencies
**In scope:** issuing a code and invalidating the previous outstanding one.

**Out of scope:** confirming and removing the link ([TASK-DP-025-010](TASK-DP-025-010.md)); sending the code to the client, which the vendor does outside the product.

**Depends on:** [TASK-DP-025-002](TASK-DP-025-002.md).

## Behavior and invariants
- Authority and locking as for the other mutations: manage code first, then the engagement row `FOR UPDATE`.
- Preconditions: engagement Active and `ClientOrganizationId` null. Otherwise 409 (`Engagement.Closed` or `Engagement.AlreadyLinked`).
- The code is generated with a cryptographic random source and at least 128 bits of entropy (proposed format: 32 Crockford base32 characters, grouped for reading). Only `SHA-256(code)` is stored in `CodeVerifier`.
- `IssuedAt` is UTC now, `ExpiresAt = IssuedAt + 7 days`, `Status = Outstanding`, `IssuedByUserId` is the caller.
- An existing outstanding code of the engagement becomes `Invalidated` in the same transaction; the partial unique index guards concurrent issues.
- The code is returned once in the response of this request. It is never logged and never written to events, history or any later read.
- An outstanding code grants no access to anyone.

## API contract (only for API tasks)
- **Route base (proposed, mirrors Identity):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/engagements`. Not exposed through the Gateway until TASK-DP-025-013.
- **Authentication and tenant:** `[Authorize]`. User ID and session ID come from `ICurrentUserProvider` (`CurrentUser.Id`, `CurrentUser.SessionId`). The workspace is the route `organizationId`, confirmed by `IWorkspaceAuthority`; it is never taken from token claims or the body (BR-008).
- **Errors (through `GlobalExceptionHandlingMiddleware`):** 400 `CqrsValidationException`; 401 no valid session; 403 `ForbiddenException` when Identity denies the workspace or the required code is missing; 404 `NotFoundException` for an engagement of another workspace or outside the caller's visibility, with the same response in both cases; 409 `ConflictException`; 503 `ServiceUnavailableException` when Identity cannot answer (fail closed).
- **Method and route (proposed):** `POST .../engagements/{engagementId:guid}/link-codes`.
- **Body:** `expectedVersion` (required).
- **Success:** 201 with `code` (once), `expiresAt` and the engagement `version`. Response headers `Cache-Control: no-store`.
- **Errors:** 403 without the manage code; 404; 409 for a Closed or already linked engagement or a stale version.

## Persistence, events and integrations
Event `link-code.issued`, `SubjectType = LinkCode`, `Details`: `{ linkCodeId, expiresAt, invalidatedLinkCodeId }`. No code, no verifier. No outbox message.

## Test matrix
- **Positive:** the response contains a code; the row holds its SHA-256 and a 7-day expiry; the detail read shows an outstanding code and its expiry but no code.
- **Second issue:** the first code becomes `Invalidated`; exactly one outstanding row exists; two parallel issues end with one outstanding code.
- **Preconditions:** Closed or already linked engagement gives 409.
- **Secrecy:** the event payload and captured log output of the request do not contain the code or the verifier.
- **Authorization and tenant:** no manage code gives 403; other workspace gives 404; Identity unavailable gives 503.
