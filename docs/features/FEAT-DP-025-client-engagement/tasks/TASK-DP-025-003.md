# TASK-DP-025-003 — List and view engagements with full detail and history

## Objective and source contract
Add the read side for the full-detail tier: paged list, engagement detail and change history, visible only to holders of `organization.engagements.read-all` or `organization.engagements.manage` and to the engagement's creator. Sources: [FR-DP-025-006](../fr/FR-DP-025-006.md), [FR-DP-025-010](../fr/FR-DP-025-010.md); [US-DP-025-006](../us/US-DP-025-006.md) AC-001 and AC-004; [US-DP-025-001](../us/US-DP-025-001.md) AC-003. All source UR/FR/US are `ready` with `approval_ref: null`: complete for planning, not client-approved.

The summary tier for project participants and the project list on the engagement page need FEAT-DP-004 tables and are planned separately in [TASK-DP-025-011](TASK-DP-025-011.md).

## Behavior and invariants
- Authority: `IWorkspaceAuthority.RequireAsync` with no required code returns the caller's effective permissions. A caller Identity does not allow in the workspace gets 403.
- Tier: full detail when the caller holds read-all or manage, or is `CreatedByUserId` of that engagement. Otherwise the engagement does not exist for the caller.
- List: read-all and manage holders get every engagement of the workspace; other members get only engagements they created; a member with none gets an empty page. Order `CreatedAt` descending, then `Id`.
- Detail returns every engagement field, contract value and effort, non-removed contacts, milestones, client-link state (`clientOrganizationId`, linked time, whether a code is outstanding and its expiry, never the code) and `version`.
- History returns the engagement's events in order, with event type, subject, actor user ID, acting organization ID, UTC time, reason, details and engagement version. Actor names are not resolved here; the Identity batch user lookup ([PRJ-20](../../../architecture/modules/projects/design-decisions.md#prj-20)) can add them later.
- Every query filters by `OrganizationId` first, then applies the tier (ADR-001 D-07). Queries open no command transaction.
- Authority is asked uncached in this task. ADR-001 D-04 allows a cache of at most 30 seconds for queries; adding one is a later optimization.

## API contract (only for API tasks)
- **Route base (proposed, mirrors Identity):** `api/v{version:apiVersion}/organizations/{organizationId:guid}/engagements`. Not exposed through the Gateway until TASK-DP-025-013.
- **Authentication and tenant:** `[Authorize]`. User ID and session ID come from `ICurrentUserProvider` (`CurrentUser.Id`, `CurrentUser.SessionId`). The workspace is the route `organizationId`, confirmed by `IWorkspaceAuthority`; it is never taken from token claims or the body (BR-008).
- **Errors (through `GlobalExceptionHandlingMiddleware`):** 400 `CqrsValidationException`; 401 no valid session; 403 `ForbiddenException` when Identity denies the workspace or the required code is missing; 404 `NotFoundException` for an engagement of another workspace or outside the caller's visibility, with the same response in both cases; 409 `ConflictException`; 503 `ServiceUnavailableException` when Identity cannot answer (fail closed).
- **Routes (proposed):**
  - `GET .../engagements?status=active|closed|all&limit=50&cursor=` (default `active`; `limit` 1–100);
  - `GET .../engagements/{engagementId:guid}`;
  - `GET .../engagements/{engagementId:guid}/history?limit=50&cursor=`.
- **Success:** 200. Lists return `items` and `nextCursor` (null on the last page). The cursor is opaque and encodes the last `(CreatedAt, Id)` or `(OccurredAt, Id)`.
- **Errors:** 400 for an invalid status, limit or cursor; 404 for an engagement in another workspace or outside the caller's tier.

## Persistence, events and integrations

## Test matrix
- **Read-all:** sees all engagements of workspace A with full detail and none of workspace B.
- **Manage only:** same visibility as read-all.
- **Creator only:** list contains only their own engagements; opening another one gives 404.
- **No tier:** empty list; 404 on direct access; 404 on history.
- **Cross-tenant:** an engagement ID of workspace A requested under workspace B gives 404 with the same body as an unknown ID.
- **Paging:** 3 pages over seeded data with stable order and no duplicates; invalid cursor gives 400.
- **History:** entries are ordered and never contain a link code or verifier.
- **Fail closed:** Identity unavailable gives 503.
