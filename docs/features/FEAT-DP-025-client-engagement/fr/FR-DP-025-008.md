# FR-DP-025-008 — Issue a client organization link code

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a holder of `organization.engagements.manage` generate a single-use link code for an Active engagement without a confirmed client link, valid for 7 days, so that the client can confirm the link.

## Preconditions and trigger
An Active engagement with no confirmed link; caller holds `organization.engagements.manage`.

## Main behavior
Generate a high-entropy single-use code, show it to the issuer once, and store only a non-reversible form with issuer, UTC issue time and expiry (issue time + 7 days). Issuing a new code invalidates any outstanding code for that engagement. The vendor sends the code to the client outside the product. The code never appears in logs, history payloads or events.

## Validation, business rules and authorization
- **User-selected (OQ-025-10):** link-code flow; ADR-001 D-09: the vendor never provisions or owns the client organization.
- An outstanding code grants no access to anyone (D-07).

## Failure and edge cases
- Engagement already linked or Closed: rejected.
- Caller without manage code: denied.

## Verification criteria
- The issuer sees the code once; later reads show only that a code is outstanding and when it expires.
- Issuing a second code makes the first unusable.

Criteria are scenarios for task planning, not executed tests.
