# FR-DP-025-001 — Create a client engagement

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let an authorized vendor workspace member create a client engagement owned by that workspace, with the client's business details and a fixed-price agreement reference.

## Preconditions and trigger
An authenticated user with a current session acts in a selected workspace and holds `organization.engagements.create` there, confirmed with Identity uncached for this command (ADR-001 D-03/D-04).

## Main behavior
Required: client display name (trimmed, 1–200 characters), agreement reference (trimmed, 1–100 characters) and agreement signed date (calendar date). Optional: client legal name (≤200), country (ISO 3166-1 alpha-2), engagement name (≤200), external document link (absolute HTTPS URL, ≤2000). Record the owning workspace, creator and UTC creation time; the contract model is fixed-price implicitly; the engagement starts Active (FR-DP-025-007). When another Active engagement in the same workspace has the same agreement reference (trimmed, case-insensitive), the result carries a duplicate warning and creation still succeeds. Creation does not create users, memberships, Identity organizations or project access.

## Validation, business rules and authorization
- The owning workspace comes from the authorized context, never from a caller-supplied ID alone (BR-008).
- **User-selected:** field set and limits (OQ-025-01/02); duplicates allowed with warning (OQ-025-11).
- Creation is attributable (BR-046, NFR-003).

## Failure and edge cases
- Missing permission, suspended or removed membership, inactive organization or revoked session: nothing is created.
- Identity unavailable: fail closed, nothing is created (D-04).
- Blank or over-length fields, invalid country code or non-HTTPS link: rejected without partial records.
- A retried identical request must not create duplicates; replay semantics are task design.

## Verification criteria
- A holder of the create permission creates an engagement visible to read-all and manage holders of the same workspace.
- A member without the permission is denied and no record exists.
- An engagement in workspace A is never returned in workspace B.
- A second engagement with an existing active agreement reference is created and the response includes the duplicate warning.
- Client display name of 201 characters and a document link using http are rejected.

Criteria are scenarios for task planning, not executed tests.
