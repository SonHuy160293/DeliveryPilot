# FR-DP-025-002 — Update engagement client details and agreement reference

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a holder of `organization.engagements.manage` update an Active engagement's client details and agreement fields, recording each change attributably.

## Preconditions and trigger
An Active engagement in the caller's workspace; the caller holds `organization.engagements.manage` confirmed with Identity uncached.

## Main behavior
Apply the change and append history (FR-DP-025-010) with old and new values, actor and UTC time. A change to the agreement reference or signed date requires a reason; other fields accept an optional reason. Concurrent edits are detected rather than silently overwritten. Field rules match FR-DP-025-001.

## Validation, business rules and authorization
- **User-selected (OQ-025-08):** edit authority is the new Identity code `organization.engagements.manage` (Owner/Admin by default, delegable).
- **User-selected (OQ-025-12):** agreement-reference changes are corrections/amendments with mandatory reason, not Change Requests; material scope changes go through FEAT-DP-019.
- BR-046: agreement changes are attributable.

## Failure and edge cases
- Closed engagement: rejected (FR-DP-025-007).
- Stale version: conflict, no change.
- Agreement reference change without reason: rejected.
- Caller without the manage code: denied without revealing whether the engagement exists beyond their visibility (FR-DP-025-006).

## Verification criteria
- An authorized edit updates the value and appends history with old/new values, actor, reason and UTC time.
- Two concurrent edits from the same version: one succeeds, the other gets a conflict.
- The engagement creator without the manage code cannot edit.

Criteria are scenarios for task planning, not executed tests.
