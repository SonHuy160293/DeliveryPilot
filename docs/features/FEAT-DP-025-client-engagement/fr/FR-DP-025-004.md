# FR-DP-025-004 — Manage engagement milestones

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Requirement statement
The system shall let a holder of `organization.engagements.manage` add, change and retire engagement milestones, preserving each milestone's original target date and recording every change attributably.

## Preconditions and trigger
An Active engagement; caller holds `organization.engagements.manage`.

## Main behavior
A milestone has name (1–200), optional description (≤2000), original target date, current target date and status. New milestones start Planned with equal original and current dates. Changing the current target date requires a reason; the original date never changes. Status transitions: Planned → Achieved, Missed or Retired; Missed → Achieved or Retired; Achieved and Retired are terminal. Retired milestones remain in history. Milestones are not linked to projects, Sprints, releases or payments in MVP.

## Validation, business rules and authorization
- **User-selected (OQ-025-05):** shape, mandatory reason and no Change Request gate in MVP.
- Calendar dates are dates; change instants are UTC (AGENTS.md).
- Milestone changes are candidate events for the Risk module (ADR-001 D-10), defined when that consumer exists.

## Failure and edge cases
- Blank name, missing date, or date change without reason: rejected.
- Changing a Retired or Achieved milestone: rejected.
- Stale version: conflict.

## Verification criteria
- A new milestone shows identical original and current dates and status Planned.
- After a date change both dates, the reason, actor and UTC time are visible.
- Moving from Achieved back to Planned is rejected.

Criteria are scenarios for task planning, not executed tests.
