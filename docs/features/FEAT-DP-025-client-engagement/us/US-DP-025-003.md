# US-DP-025-003 — Record contract value and planned effort

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Story
As a vendor engagement manager, I want to record the contract value and planned effort, so that delivery can be compared against the fixed-price envelope.

## Context and boundaries
Internal values; never shown to guests or summary-tier participants.

## Acceptance criteria
### AC-001 — Record values
**Given** an Active engagement **When** I enter 120000.00 USD and 400 person-days **Then** the values are stored and visible to full-detail users.

### AC-002 — Invalid values
**Given** an Active engagement **When** I enter an unknown currency code or a negative amount **Then** the change is rejected.

### AC-003 — Currency lock
**Given** an amount in USD is set **When** I try to change the currency to EUR **Then** the change is rejected until the amount is cleared.

### AC-004 — Participant cannot see
**Given** Bob participates in a project under the engagement without read-all or manage **When** Bob opens the engagement summary **Then** no contract value or effort is shown.

## Dependencies and testing notes
Participant case depends on FEAT-DP-004 participation.
