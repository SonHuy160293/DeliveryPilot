# US-DP-025-002 — Correct engagement details with history

**Provenance:** Drafted 2026-11-09 with `dp-feature-engineer` from the roadmap, requirements, workflow discovery and [ADR-001](../../../architecture/adr-001-delivery-module-placement.md). Business choices marked **User-selected** were made by the user in the joint feature review on 2026-11-09 (see the decision record in [feature.md](../feature.md)). `ready` records internal completeness review for task planning, not client approval; `approval_ref` stays null and nothing here is implemented.

## Story
As a vendor engagement manager, I want to correct client details or the agreement reference, so that the record stays accurate while past values stay traceable.

## Context and boundaries
Needs the Identity code `organization.engagements.manage` (TASK-DP-003-022).

## Acceptance criteria
### AC-001 — Attributable edit
**Given** an Active engagement and I hold the manage code **When** I change the agreement reference with a reason **Then** the new value is shown and history shows old value, new value, me, the reason and UTC time.

### AC-002 — Reason required
**Given** I hold the manage code **When** I change the agreement reference without a reason **Then** the change is rejected.

### AC-003 — Concurrent edit
**Given** two managers opened the same engagement version **When** both save changes **Then** one succeeds and the other receives a conflict.

### AC-004 — No authority
**Given** I created the engagement but do not hold the manage code **When** I try to edit it **Then** the change is rejected.

## Dependencies and testing notes
History entries must be append-only in tests.
